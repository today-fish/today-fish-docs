# PF-003 Price Insight

> **핵심 결론:** Price Insight는 사용자가 선택한 수산물의 가격 기간에 대해 가격 데이터, 확인된 사실, AI의 가능한 해석을 함께 제공하는 핵심 기능이다. 분석은 하루 1회 자동 수행해 저장하며, 사용자 조회 시 저장된 결과를 제공한다. 최대 3개의 가격 변동 가능 요인을 제시하되, 인과관계가 검증되지 않은 요인을 확정적인 원인으로 표현하지 않는다. AI 분석이 없더라도 가격과 확인된 사실은 유지하고 AI 해석만 `파악 중`으로 표시한다.

## 1. 기능 목적

Price Insight는 수산물 가격이 어떻게 변했는지 보여주는 것을 넘어, 해당 가격 변화와 관련된 사실 및 가능한 배경을 이해하도록 돕는다.

수산물 가격 변화는 생산량, 공급 상황, 수요, 유통 환경, 기상 조건, 정책 및 국제 정세 등 다양한 요인의 영향을 받을 수 있다.

하지만 특정 시기의 가격 변화와 외부 요인이 동시에 발생했다는 사실만으로 인과관계가 입증되는 것은 아니다.

따라서 Price Insight는 다음 세 가지를 구분한다.

1. 실제 가격 데이터로 확인되는 가격 변화
2. 뉴스 및 공공기관 자료로 확인되는 사실
3. 사실과 가격 흐름을 바탕으로 AI가 제시하는 가능한 해석

### 1.1 사용자 목표

- 선택한 기간의 평균가격을 확인한다.
- 해당 기간의 가격 변화를 이해한다.
- 가격 변화와 관련된 확인된 사실을 살펴본다.
- 최대 3개의 가격 변동 가능 요인을 확인한다.
- 설명의 근거와 원문을 직접 확인한다.
- 확인되지 않은 정보를 확정적 사실로 오인하지 않는다.

### 1.2 핵심 원칙

- 가격 데이터와 AI 해석을 구분한다.
- 확인된 사실과 가능한 해석을 구분한다.
- AI의 추론을 검증된 인과관계로 표현하지 않는다.
- 근거가 부족하면 무리하게 분석하지 않는다.
- AI가 설명할 수 없는 내용은 `파악 중`으로 표시한다.
- 출처를 확인할 수 없는 주장을 사실로 제공하지 않는다.
- AI 분석 실패가 가격 차트의 정상 동작에 영향을 주지 않는다.
- 사용자 조회마다 AI를 실행하지 않는다.

## 3. Price Insight 구성

### 3.1 화면 구성

Price Insight는 다음 정보를 제공한다.

| 영역 | 정보 |
|---|---|
| 분석 대상 | 수산물명 |
| 분석 기간 | 시작일~종료일 |
| 가격 정보 | 선택 기간 평균가격 |
| 가격 변화 | 비교 가능한 경우 가격 변화 방향 및 변동률 |
| 확인된 사실 | 공공데이터·뉴스 등으로 확인된 정보 |
| 가능한 해석 | AI가 도출한 가격 변동 가능 요인 |
| 분석 상태 | 분석 완료 또는 파악 중 |
| 출처 정보 | 출처 이름·문서 제목·발행일·원문 링크 |

### 3.2 정보 표시 순서

Price Insight는 다음 순서로 표시하는 것을 기본 설계안으로 한다.

1. 선택한 분석 기간
2. 해당 기간 평균가격
3. 확인된 가격 변화
4. 확인된 사실
5. 가능한 해석
6. 관련 출처

위 표시 순서는 UI 설계 제안이며, 추후 디자인 단계에서 변경할 수 있다.

단, 확인된 사실과 가능한 해석을 시각적으로 구분하는 요구사항은 유지한다.

### 3.3 최초 진입 상태

수산물 상세 화면에 최초 진입하면 선택된 가격 기간이 없다.

따라서 Price Insight는 자동으로 특정 기간을 분석하지 않는다.

**안내 문구 예시**

"차트에서 궁금한 기간을 선택하면 가격 변화에 대한 분석을 확인할 수 있습니다."

### 인수 조건

- [ ] 상세 화면 최초 진입 시 Price Insight가 자동 선택되지 않는다.
- [ ] 기간 선택 안내가 표시된다.
- [ ] 사용자가 가격 차트에서 기간을 선택하면 해당 기간의 분석이 표시된다.
- [ ] 가격 차트의 집계 단위를 전환하면 분석 선택 상태가 해제된다.

## 4. Price Insight 분석 대상

### 4.1 분석 단위

분석 결과는 다음 조합을 기준으로 식별한다.

- 수산물 식별자
- 가격 집계 단위
- 기간 시작일
- 기간 종료일

집계 단위는 다음 두 가지다.

| 집계 단위 | 분석 범위 |
|---|---|
| HALF_MONTH | 1~15일 또는 16일~말일 |
| MONTH | 해당 월 전체 |

### 4.2 반월 분석

15일 가격 차트에서 특정 기간을 선택하면 해당 반월 전체에 대한 분석을 제공한다.

예시:

- 수산물: 갈치
- 집계 단위: HALF_MONTH
- 선택 기간: 2026-08-01~2026-08-15

시스템은 해당 기간에 연결된 가격 데이터와 근거 자료를 기반으로 생성한 저장된 분석을 반환한다.

### 4.3 월별 분석

월별 차트에서 특정 월을 선택하면 해당 월 전체의 분석을 제공한다.

예시:

- 수산물: 갈치
- 집계 단위: MONTH
- 선택 기간: 2026-08-01~2026-08-31

월별 분석은 두 반월 분석을 단순 결합한 결과로 대체하지 않는다.

월 전체의 가격 변화와 관련 자료를 분석한 별도 결과를 제공한다.

### 4.4 분석 기간 변경

사용자가 다른 가격 점을 선택하면 다음 정보가 함께 변경된다.

- 분석 대상 기간
- 기간 평균가격
- 해당 기간의 가격 변화 정보
- 확인된 사실
- 가능한 해석
- 관련 출처

이전 기간의 분석 내용이 새로운 선택 기간에 남아서는 안 된다.

## 5. 분석 데이터

### 5.1 가격 데이터

가격 분석의 기준은 KAMIS 대표 가격 데이터다.

- 국산 생물로 분류된 적격 관측값 사용
- 여러 시장의 단순평균 적용
- 일별 시장 평균 후 기간별 평균 산출
- 관측일 수 및 시장 수 보존
- 가격 결측 구간은 임의 보정하지 않음

구체적인 가격 계산과 유효성 판단은 PP-001을 따른다.

### 5.2 공공데이터

공공데이터포털의 공영도매시장 정산정보는 다음 데이터를 제공할 수 있다.

- 거래량
- 정산금액
- 정산가격 관련 통계
- 시장별 거래 현황

단, KAMIS와 정산정보의 품목군 수준 코드 매핑만으로 세부 상품이 동일하다고 보장할 수 없다.

따라서 다음 사항을 준수한다.

- 정산정보의 거래량을 KAMIS 대표 가격의 직접적인 원인으로 단정하지 않는다.
- 세부 상품 매핑이 검증되지 않았다면 동일 상품의 가격·거래량인 것처럼 비교하지 않는다.
- 비교 가능한 범위와 한계를 분석 결과에 반영한다.
- 거래량 변화와 가격 변화의 방향이 일치하더라도 인과관계가 성립한다고 결론 내리지 않는다.

### 5.3 뉴스 및 공공기관 자료

Price Insight는 다음 유형의 자료를 근거로 활용할 수 있다.

- 수산물 관련 뉴스 기사
- 공공기관 발표 자료
- 생산량 및 수급 관련 공개 통계
- 정책 및 제도 변경 관련 자료
- 기상 및 해양 환경 관련 공개 자료
- 수출입 관련 공개 자료

위 자료들은 활용 가능한 근거의 유형을 나타내며, 각 유형의 데이터 수집 연계가 모두 검증되었다는 의미는 아니다.

### 5.4 과거 자료 활용

Price Insight는 현재 최근 30일에 발행된 자료만 사용하는 기능이 아니다.

사용자가 과거 가격 기간을 선택하면 해당 기간과 관련된 과거 뉴스 및 공공기관 자료를 활용할 수 있어야 한다.

예시:

2026년 2월 가격 기간을 분석할 경우, 현재의 최근 30일 기사 목록만 조회해서는 안 된다.

선택한 기간에 관련되는 자료를 별도로 조회해야 한다.

자료의 발행일과 실제 사건 발생일이 다를 수 있으므로, 기간 관련성 판단 기준은 PP-002에서 정의한다.

## 6. 정보 신뢰 수준

### 6.1 분류 원칙

Price Insight는 다음 세 가지 정보 상태를 구분한다.

| 구분 | 의미 | 표시 원칙 |
|---|---|---|
| 확인된 사실 | 출처 또는 실제 데이터로 확인 가능한 사실 | 출처와 함께 제공 |
| 가능한 해석 | 확인된 사실을 기반으로 AI가 제시한 설명 가능성 | 가능성 표현 사용 |
| 파악 중 | 분석이 없거나 근거가 부족해 해석할 수 없는 상태 | 확정 설명 생성 금지 |

### 6.2 확인된 사실

확인된 사실은 원천 가격 데이터 또는 신뢰할 수 있는 출처에서 직접 확인할 수 있는 정보다.

**예시**

"해당 기간 갈치의 평균가격은 12,000원/kg으로 집계되었습니다."

"공공기관이 해당 기간의 수산물 생산 동향 자료를 발표했습니다."

단, 두 사실이 동시에 존재한다는 이유만으로 가격 변화의 인과관계를 확정할 수는 없다.

**요구사항**

- 사실은 확인 가능한 데이터 또는 문서를 근거로 한다.
- 수치와 원문 내용이 일치해야 한다.
- 출처가 제공되는 사실에는 출처 정보를 연결한다.
- AI가 생성한 추정을 사실처럼 표시하지 않는다.
- 외부 자료의 주장과 실제 검증된 사실을 혼동하지 않는다.

### 6.3 가능한 해석

가능한 해석은 확인된 사실과 가격 데이터 사이의 관계에 대해 AI가 제시한 설명이다.

**허용 표현 예시**

"같은 시기에 확인된 공급 변화가 가격 흐름과 관련되었을 가능성이 있습니다."

"해당 기간의 수급 상황이 가격 변화에 영향을 주었을 수 있습니다."

**금지 표현 예시**

"거래량이 증가했기 때문에 가격이 하락했습니다."

"이번 가격 상승은 특정 정책이 원인입니다."

단, 해당 인과관계가 독립적으로 충분히 검증된 경우에 대한 별도 정책은 후속 검토 대상이다.

MVP에서는 검증되지 않은 인과관계를 확정적으로 표현하지 않는다.

### 6.4 파악 중

다음 경우에는 AI 해석을 `파악 중`으로 표시한다.

- 해당 기간 분석이 아직 생성되지 않음
- AI 분석 생성 실패
- 가격 변화와 관련된 충분한 근거 부족
- 출처 검증 실패
- 기존 분석이 무효화되어 재분석 필요

**중요**

AI 해석이 파악 중이라고 해서 가격 데이터와 확인된 사실까지 숨기지 않는다.

가격과 확인된 사실은 각각의 데이터 유효성에 따라 독립적으로 제공한다.

## 7. 가격 변동 가능 요인

### FR-INSIGHT-01. 최대 3개 요인 제공

**요구사항**

선택한 가격 기간에 대해 최대 3개의 가격 변동 가능 요인을 제공한다.

**상세 조건**

- 근거를 확인할 수 있는 요인만 제공한다.
- 반드시 3개를 채울 필요는 없다.
- 근거가 부족하면 0~2개를 제공할 수 있다.
- 같은 근거를 반복해 요인 수를 인위적으로 늘리지 않는다.
- 가능한 해석과 확인된 사실을 구분한다.

**인수 조건**

- [ ] 가능한 요인이 1개일 때 1개만 표시할 수 있다.
- [ ] 가능한 요인이 2개일 때 2개만 표시할 수 있다.
- [ ] 요인이 4개 이상 도출되어도 최대 3개만 표시한다.
- [ ] 근거가 없을 때 요인을 임의 생성하지 않는다.
- [ ] 모든 해석 요인은 연결된 근거를 추적할 수 있다.

### FR-INSIGHT-02. 요인 설명

각 요인에 포함될 정보는 다음과 같다.

| 항목 | 설명 |
|---|---|
| 요인 제목 | 관련된 현상이나 사건 |
| 요인 설명 | 가격 흐름과의 가능한 관계 |
| 정보 구분 | 가능한 해석 |
| 관련 근거 | 연결된 뉴스·공공자료 |
| 출처 정보 | 출처명, 제목, 발행일, URL |

요인의 중요도 순위 또는 신뢰도 점수는 아직 확정하지 않는다.

수치형 신뢰도 점수를 객관적 확률처럼 표시하지 않는다.

## 8. 분석 생성 및 저장

### FR-INSIGHT-03. 하루 1회 자동 분석

**요구사항**

Price Insight는 하루 1회 자동 분석해 저장한다.

**처리 흐름**

1. 가격 데이터 수집 및 집계 결과 확인
2. 관련 뉴스·공공기관 자료 확인
3. 분석 대상 품목과 기간 선정
4. 확인된 사실 구성
5. AI를 이용한 가능한 해석 생성
6. 근거 및 표현 검증
7. 분석 결과 저장
8. 사용자 조회 시 저장 결과 반환

**상세 조건**

- 사용자 조회마다 LLM을 호출하지 않는다.
- 분석 결과는 품목과 기간에 연결한다.
- 동일 기간의 재분석이 가능해야 한다.
- 생성 실패를 기록한다.
- 분석 결과가 없을 때 가격 조회는 유지한다.

**인수 조건**

- [ ] 자동 분석 작업을 하루 1회 실행할 수 있다.
- [ ] 생성된 분석을 저장할 수 있다.
- [ ] 같은 품목·기간 조회 시 저장된 결과를 반환한다.
- [ ] 사용자 조회가 실시간 LLM 호출에 의존하지 않는다.
- [ ] 분석 실패 상태를 확인할 수 있다.

### FR-INSIGHT-04. 분석 결과 버전 관리

**요구사항**

과거 분석 결과는 새로운 근거 또는 가격 데이터 변경 시 갱신할 수 있어야 한다.

**갱신 조건**

- 원천 가격 데이터 정정
- 기간별 가격 집계 결과 변경
- 관련성이 있는 새로운 근거 자료 추가
- 기존 근거 자료의 정정 또는 무효화

**상세 조건**

- 재분석 대상 기간을 식별할 수 있어야 한다.
- 기존 분석과 새 분석을 구분할 수 있어야 한다.
- 현재 사용자에게 제공할 유효 분석을 식별해야 한다.
- 분석의 생성일과 갱신일을 추적할 수 있어야 한다.
- 이전 분석을 보관하는 방식과 보관 기간은 PP-002에서 결정한다.

**인수 조건**

- [ ] 원천 가격 변경 시 영향받는 기간을 식별할 수 있다.
- [ ] 관련 근거 추가 시 해당 기간을 재분석 대상으로 지정할 수 있다.
- [ ] 재분석 결과와 기존 결과를 구분할 수 있다.
- [ ] 사용자에게 무효화된 결과를 정상 분석으로 제공하지 않는다.

### FR-INSIGHT-05. 선택 기간 분석 조회

**인수 조건**

- [ ] 집계 단위 전환 시 기존 분석 선택이 해제된다.
- [ ] 분석 결과가 없어도 가격 정보는 유지된다.

### FR-INSIGHT-06. 출처 원문 조회

**요구사항**

사용자는 분석 근거의 원문을 확인할 수 있어야 한다.

- 문서 또는 기사 제목

**상세 조건**

- 실제 근거와 연결된 URL을 제공한다.
- 존재하지 않는 출처를 생성하지 않는다.
- 원문 링크는 외부 사이트로 이동한다.
- 원문은 새 탭에서 연다.
- URL이 없거나 검증되지 않은 자료는 정상 근거 링크인 것처럼 표시하지 않는다.

**인수 조건**

- [ ] 사실 및 해석에 연결된 근거를 확인할 수 있다.
- [ ] 근거의 출처명과 제목을 확인할 수 있다.
- [ ] 발행일을 확인할 수 있다.
- [ ] 원문 링크를 새 탭에서 열 수 있다.
- [ ] 존재하지 않는 URL을 정상 링크로 표시하지 않는다.

## 10. AI 역할 분리

### 10.1 데이터 수집·정리 단계

가격 및 외부 근거 자료를 수집하고 분석 가능한 상태로 정리한다.

**책임**

- 원천 데이터 수집
- 기사 및 공공자료 메타데이터 수집
- 중복 자료 식별
- 출처 보존
- 자료 발행일 보존
- 분석 대상 기간과 자료의 연관성 판단 지원

### 10.2 AI 해석 단계

수집·검증된 데이터를 바탕으로 가능한 가격 변동 배경을 설명한다.

**책임**

- 가격 변화 정보 활용
- 관련 사실을 종합
- 가능한 설명 후보 생성
- 최대 3개 요인 정리
- 인과관계 단정 회피
- 근거 부족 시 파악 중 처리

### 10.3 역할 분리 원칙

- 자료 수집과 AI 해석은 논리적으로 분리한다.
- 원본 데이터와 AI 생성 결과를 별도로 보존한다.
- AI 해석이 원본 데이터를 수정하지 않는다.
- AI가 존재하지 않는 통계·기사·기관 발표를 생성해서는 안 된다.
- LLM의 출력만으로 사실 검증이 완료되었다고 간주하지 않는다.

실제 서비스 구성요소 수, 모델 수, 프롬프트 구조는 기술 설계 단계에서 결정한다.

## 12. 예외 및 실패 처리

### 12.1 가격은 있지만 AI 분석이 없는 경우

- 가격 정보는 정상 표시한다.
- 확인된 사실이 있으면 표시한다.
- AI 해석 영역에 `파악 중`을 표시한다.
- AI 분석의 부재를 가격 결측으로 처리하지 않는다.

### 12.2 근거 자료가 부족한 경우

- 근거가 부족한 내용을 억지로 해석하지 않는다.
- 요인 개수를 3개까지 채울 필요가 없다.
- 충분한 근거가 없으면 `파악 중`으로 표시한다.

### 12.3 출처를 검증할 수 없는 경우

- 출처가 검증되지 않은 주장을 확인된 사실로 표시하지 않는다.
- 해당 자료를 근거로 한 가능한 해석의 게시 여부를 검토한다.
- 출처 검증 실패 상태를 기록한다.

### 12.4 분석 중 원천 가격 데이터가 변경된 경우

- 분석이 참조한 가격 데이터의 버전을 식별할 수 있어야 한다.
- 가격 데이터 변경의 영향 범위를 확인한다.
- 필요 시 기존 결과를 재분석 대상으로 지정한다.
- 서로 다른 데이터 버전의 결과를 혼동하지 않는다.

### 12.5 같은 기간에 분석이 중복 실행되는 경우

- 동일 품목·기간·분석 버전에서 중복 실행을 식별할 수 있어야 한다.
- 중복 실행으로 정상 결과가 예기치 않게 덮어써지지 않도록 한다.
- 실제 동시성 제어 방식은 PP-002에서 결정한다.

### 12.6 과거에 발행된 자료가 뒤늦게 수집된 경우

- 발행일과 수집일을 구분한다.
- 실제로 관련된 과거 가격 기간을 식별한다.
- 해당 기간에 대한 재분석 필요성을 평가한다.
- 최근 이슈의 최근 30일 정책과 별개로 처리한다.

### 12.7 관련성이 없는 기사만 수집된 경우

- 단순 키워드 일치만으로 관련 근거라고 확정하지 않는다.
- 관련성이 확인되지 않은 자료를 가격 변동 요인으로 단정하지 않는다.
- 충분한 근거가 없으면 `파악 중`으로 처리한다.

### 12.8 외부 원문 링크가 만료된 경우

- 정상 링크인 것처럼 접근 가능성을 보장하지 않는다.
- 원문 접근 실패 여부를 확인할 수 있는 운영 정책을 마련한다.
- 링크 만료 또는 자료 삭제 시 해당 근거의 유효성을 재검토한다.

## 14. 비기능 요구사항

### 14.1 데이터 신뢰성

- 가격과 AI 해석을 별도로 관리한다.
- 원본 출처와 분석 결과를 연결한다.
- 사실과 가능한 해석을 구분한다.
- 인과관계가 검증되지 않은 내용을 단정하지 않는다.
- 원본 데이터가 정정되면 관련 분석을 추적할 수 있어야 한다.

### 14.2 운영 비용

- 사용자 조회마다 LLM을 호출하지 않는다.
- 하루 1회 사전 분석을 기본 운영 방식으로 한다.
- 이미 유효한 분석 결과를 재사용할 수 있어야 한다.
- 불필요한 중복 분석을 방지한다.
- 재분석 대상과 실행 결과를 확인할 수 있어야 한다.

### 14.3 장애 독립성

- AI 분석 장애가 가격 차트 장애로 이어지지 않도록 한다.
- 외부 근거 수집 실패와 AI 분석 실패를 구분한다.
- 부분 실패 상태에서도 정상 데이터는 제공한다.
- 장애 원인을 추적할 수 있어야 한다.

### 14.4 보안

- 외부 API 인증정보를 사용자에게 노출하지 않는다.
- AI 호출 인증정보를 클라이언트에 전달하지 않는다.
- 외부 자료에 포함된 지시문을 시스템 명령으로 신뢰하지 않는다.
- 외부 링크 및 사용자에게 노출되는 텍스트의 안전한 렌더링을 적용한다.

### 14.5 성능

다음 항목의 목표 수치는 PP-003에서 결정한다.

- 저장된 Insight 조회 응답시간
- Price Insight 최초 표시시간
- 하루 1회 배치 완료시간
- 분석 생성 성공률
- 분석 결과 재사용률
- 재분석 지연 허용시간

## 16. 출시 인수 기준

### 16.1 기능

- [ ] 차트에서 선택한 반월 또는 월의 분석을 조회할 수 있다.
- [ ] 최초 진입 시 기간 선택 안내를 제공한다.
- [ ] 기간 변경 시 분석 결과가 함께 변경된다.
- [ ] 집계 단위 변경 시 분석 선택 상태가 해제된다.
- [ ] 가격과 확인된 사실 및 가능한 해석을 구분해 표시한다.
- [ ] 가능한 요인을 최대 3개 제공한다.
- [ ] 근거 부족 시 무리하게 요인을 생성하지 않는다.

### 16.2 데이터 신뢰성

- [ ] Price Insight의 가격 정보가 선택 기간의 차트 데이터와 일치한다.
- [ ] 모든 게시된 확인 사실은 근거를 추적할 수 있다.
- [ ] 가능한 해석은 검증된 사실과 구분된다.
- [ ] 미검증 인과관계를 확정적으로 표현하지 않는다.
- [ ] 출처명·문서 제목·발행일·원문 링크를 제공한다.
- [ ] 과거 가격 기간의 분석에 관련된 과거 근거 자료를 활용할 수 있다.

### 16.3 운영

- [ ] 하루 1회 자동 분석을 실행할 수 있다.
- [ ] 분석 결과를 저장하고 재조회할 수 있다.
- [ ] 사용자 조회 시 매번 LLM을 호출하지 않는다.
- [ ] 분석 실패 시 가격과 확인된 사실을 유지한다.
- [ ] 원천 데이터 변경에 따른 재분석 대상을 식별할 수 있다.
- [ ] 분석 생성 및 실패 이력을 확인할 수 있다.
- [ ] 승인된 성능 및 성공률 기준을 충족한다.
