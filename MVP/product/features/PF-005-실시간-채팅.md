# PF-005 실시간 채팅

> **핵심 결론:** 오늘의 수산 MVP는 갈치·고등어·전복 상세 화면에 품목별 실시간 채팅방을 제공한다. 이용자는 회원가입·로그인 없이 메시지를 주고받으며, 가격 차트와 Price Insight를 보면서 같은 품목에 관한 의견을 나눌 수 있다.
>
> - 문서 상태: DRAFT
> - 상위 문서: [PRD-001 MVP 제품 요구사항](../PRD-001-MVP-제품-요구사항.md)
> - 상위 기능: `CAP-CHAT`
> - 관련 기능: [PF-001 홈 화면](./PF-001-홈-화면.md), [PF-002 수산물 가격 차트](./PF-002-수산물-가격-차트.md), [PF-003 Price Insight](./PF-003-Price-Insight.md)
> - 적용 플랫폼: 모바일 웹
> - 우선순위: MVP 필수

---

## 1. 기능 목적

실시간 채팅은 같은 수산물의 가격과 시장 정보를 보고 있는 이용자가 해당 품목에 관한 의견을 즉시 나누도록 한다.

### 사용자 목표

1. 로그인 없이 품목별 채팅방에 진입한다.
2. 현재 표시 이름과 연결 상태를 확인한다.
3. 메시지를 전송하고 다른 이용자의 메시지를 실시간으로 수신한다.
4. 가격 차트와 Price Insight를 확인하면서 채팅을 함께 이용한다.

### MVP 설계 원칙

- 회원가입·로그인·영구 프로필을 요구하지 않는다.
- 갈치·고등어·전복의 채팅방을 분리한다.
- 메시지 송수신과 연결 상태에 집중한다.
- 채팅 메시지는 공식 가격 정보나 검증된 Evidence로 취급하지 않는다.
- 고급 커뮤니티 기능보다 안정적인 기본 경험을 우선한다.

## 2. MVP 기능 범위

### 2.1 포함 기능

| 기능 | 설명 | 우선순위 |
|---|---|---|
| 품목별 채팅방 | 갈치·고등어·전복별 독립 채팅방 | MUST |
| 익명 참여 | 회원가입·로그인 없는 채팅 참여 | MUST |
| 메시지 송수신 | 텍스트 메시지 전송 및 실시간 수신 | MUST |
| 임시 표시 이름 | 참여자를 구분하는 비영구 표시 이름 | MUST |
| 작성 시각 | 메시지 작성 시각 표시 | MUST |
| 연결 상태 | 연결 중·연결됨·연결 끊김 표시 | MUST |
| 재연결 | 연결 종료 후 자동 또는 수동 재연결 | MUST |
| 입력 제한 | 길이와 전송 빈도 제한 | MUST |

### 2.2 제외 기능

- 회원가입·로그인·로그아웃
- 영구 사용자 프로필과 계정 복구
- 1:1 메시지와 비공개 채팅방
- 이미지·파일·음성 첨부
- 메시지 반응과 스레드
- 사용자 역할 Badge와 사업자 인증
- 팔로우·친구·초대
- 푸시 알림
- 고급 Moderation 도구

## 3. 화면 구성

품목 상세 화면에서 가격 차트와 Price Insight를 확인한 뒤 같은 품목의 채팅방을 이용할 수 있게 한다.

| 영역 | 표시 정보 |
|---|---|
| 채팅방 제목 | 품목명과 채팅방 표시 |
| 연결 상태 | 연결 중·연결됨·연결 끊김 |
| 메시지 목록 | 표시 이름, 메시지, 작성 시각 |
| 메시지 입력 | 텍스트 입력과 전송 버튼 |
| 상태 안내 | 재연결·전송 실패·이용 제한 안내 |

채팅은 가격 데이터와 시각적으로 구분하고, 사용자 메시지가 공식 정보로 오인되지 않도록 안내한다.

---

## 4. 사용자 흐름

### 4.1 정상 흐름

1. 이용자가 갈치·고등어·전복 중 하나의 상세 화면에 진입한다.
2. 시스템이 해당 품목의 채팅방에 연결한다.
3. 이용자는 임시 표시 이름과 연결 상태를 확인한다.
4. 기존 표시 범위의 메시지를 조회한다.
5. 텍스트 메시지를 작성해 전송한다.
6. 같은 채팅방의 다른 이용자가 메시지를 실시간으로 수신한다.

### 4.2 재연결 흐름

1. 네트워크 또는 서버 상태로 연결이 끊긴다.
2. 화면에 연결 끊김 상태를 표시한다.
3. 자동 또는 수동으로 재연결한다.
4. 재연결 성공 후 중복 없이 최신 메시지 상태를 복구한다.

---

## 5. 기능 요구사항

### FR-CHAT-01. 품목별 채팅방

- 갈치·고등어·전복에 각각 독립된 채팅방을 제공한다.
- 메시지는 `species_id`로 구분한다.
- 한 품목의 메시지를 다른 품목 채팅방에 표시하지 않는다.

### FR-CHAT-02. 인증 없는 참여

- 회원가입과 로그인을 요구하지 않는다.
- 참여자를 구분하기 위한 임시 식별자와 표시 이름을 사용할 수 있다.
- 임시 식별자를 영구 회원 계정처럼 표현하지 않는다.
- 개인정보 입력을 기본 참여 조건으로 요구하지 않는다.

### FR-CHAT-03. 메시지 전송

- 연결된 이용자는 허용 범위의 텍스트 메시지를 전송할 수 있다.
- 빈 메시지와 허용 길이를 초과한 메시지는 거부한다.
- 전송 성공·실패 상태를 확인할 수 있어야 한다.
- 중복 전송을 식별할 수 있는 메시지 ID를 사용한다.

### FR-CHAT-04. 메시지 수신

- 같은 품목 채팅방의 새 메시지를 실시간으로 수신한다.
- 메시지에는 식별자, 품목, 표시 이름, 본문, 작성 시각이 포함된다.
- 수신 순서를 판단할 수 있는 서버 기준 시각 또는 순서 정보가 필요하다.

### FR-CHAT-05. 연결과 재연결

- 연결 중·연결됨·연결 끊김 상태를 구분한다.
- 연결이 끊기면 재연결을 시도하거나 사용자가 다시 연결할 수 있게 한다.
- 재연결 과정에서 같은 메시지를 반복 표시하지 않는다.
- 재연결에 실패해도 가격 차트와 Price Insight 이용을 막지 않는다.

### FR-CHAT-06. 기본 이용 제한

- 메시지 길이 제한을 적용한다.
- 사용자 또는 연결 단위의 전송 빈도 제한을 적용한다.
- 유효하지 않은 입력과 과도한 전송을 거부한다.
- 제한에 걸린 경우 사용자에게 전송 실패 상태를 안내한다.

## 6. 채팅 데이터 계약

### 6.1 채팅방 식별

| 필드 | 의미 |
|---|---|
| room_id | 채팅방 식별자 |
| species_id | 갈치·고등어·전복 품목 식별자 |
| connection_status | 연결 상태 |

### 6.2 메시지

| 필드 | 의미 |
|---|---|
| message_id | 메시지 식별자 |
| room_id | 채팅방 식별자 |
| species_id | 품목 식별자 |
| participant_id | 비영구 참여자 식별자 |
| display_name | 임시 표시 이름 |
| content | 메시지 본문 |
| created_at | 서버 기준 작성 시각 |

구체적인 API 경로, 실시간 전송 방식과 저장소는 기술 설계에서 결정한다.

## 7. 상태 및 오류 처리

| 상태 | 처리 |
|---|---|
| 연결 중 | 채팅 연결 진행 상태 표시 |
| 연결됨 | 메시지 조회와 전송 허용 |
| 연결 끊김 | 상태 안내 및 재연결 제공 |
| 전송 중 | 중복 전송을 방지하고 진행 상태 표시 |
| 전송 실패 | 실패 표시와 재시도 가능 여부 안내 |
| 제한됨 | 길이·빈도 제한 사유 안내 |

채팅 오류는 가격 차트, Price Insight와 최근 이슈 조회에 영향을 주지 않아야 한다.

## 8. 비기능 요구사항

### 8.1 성능

- 단일 수산물 채팅방 동시 접속자 500명을 초기 목표로 고려한다.
- 사용자 1명당 최대 초당 5개 메시지 전송 상황을 성능 검증 범위에 포함한다.
- 정확한 부하 테스트 방법과 허용 지연은 기술 설계에서 확정한다.

### 8.2 안정성

- 일시적 연결 종료 후 재연결할 수 있어야 한다.
- 중복 또는 순서가 뒤바뀐 메시지를 식별할 수 있어야 한다.
- 채팅 장애가 읽기 전용 핵심 기능으로 전파되지 않아야 한다.

### 8.3 최소 안전 기준

- 메시지를 실행 가능한 코드나 신뢰된 명령으로 처리하지 않는다.
- 허용하지 않는 입력과 과도한 전송을 제한한다.
- 운영상 필요한 메시지 식별 정보와 시각을 추적할 수 있어야 한다.
- 신고·차단·금칙어의 MVP 범위는 출시 전 확정한다.

## 11. 출시 인수 기준

- [ ] 회원가입·로그인 없이 채팅방에 진입할 수 있다.
- [ ] 갈치·고등어·전복 채팅방이 서로 분리된다.
- [ ] 메시지를 전송하고 실시간으로 수신할 수 있다.
- [ ] 임시 표시 이름과 작성 시각을 확인할 수 있다.
- [ ] 연결 상태와 전송 실패 상태를 구분한다.
- [ ] 연결 종료 후 재연결할 수 있다.
- [ ] 메시지 길이와 전송 빈도 제한이 작동한다.
- [ ] 채팅 장애가 가격·Insight 조회에 영향을 주지 않는다.
- [ ] 최소 Moderation 범위가 출시 전에 확정된다.
