# PF-005 실시간 채팅

> **핵심 결론:** 오늘의 수산 MVP는 갈치·고등어·전복 상세 화면에 품목별 실시간 채팅방을 제공한다. 메시지는 최대 300 Unicode 문자, 서버 검증 세션당 3초 1회·분당 20회로 제한하고 최근 50개만 조회하며 7일 보존한다. 서버 금칙어 검사는 필수이고, 같은 브라우저·같은 품목의 다중 탭은 하나의 익명 참여자 세션을 공유한다. 품목별 500명과 정상 메시지 전달 p95 500ms는 출시 필수다.
>
> - 문서 상태: DRAFT — 승인된 익명 식별·세션 정책 반영
> - 상위 문서: [PRD-001 MVP 제품 요구사항](../PRD-001-MVP-제품-요구사항.md)
> - 상위 기능: `CAP-CHAT`
> - 관련 기능: [PF-001 홈 화면](./PF-001-홈-화면.md), [PF-002 수산물 가격 차트](./PF-002-수산물-가격-차트.md), [PF-003 Price Insight](./PF-003-Price-Insight.md)
> - 관련 정책: [PP-003 MVP 출시 인수 기준](../policies/PP-003-MVP-출시-인수-기준.md)

> - 우선순위: MVP 필수

## 1. 기능 목적

실시간 채팅은 같은 수산물의 가격과 시장 정보를 보고 있는 이용자가 해당 품목에 관한 의견을 즉시 나누도록 한다.

### 사용자 목표

1. 로그인 없이 품목별 채팅방에 진입한다.
2. 자동 할당된 닉네임·색상과 연결 상태를 확인한다.
3. 메시지를 전송하고 다른 이용자의 메시지를 실시간으로 수신한다.
4. 연결이 끊겼을 때 기존 익명 조합으로 복원한다.
5. 가격 차트와 Price Insight를 확인하면서 채팅을 함께 이용한다.

### MVP 설계 원칙

- 회원가입·로그인·영구 프로필을 요구하지 않는다.
- 갈치·고등어·전복의 채팅방을 분리한다.
- 익명 조합의 할당과 소유 여부는 서버가 검증한다.
- 채팅 메시지는 공식 가격 정보나 검증된 Evidence로 취급하지 않는다.
- 채팅 장애가 가격·분석·이슈 조회를 막지 않는다.

| 영역 | 표시 정보 |
|---|---|
| 채팅방 제목 | 품목명과 채팅방 표시 |
| 참여자 표시 | 자동 할당 닉네임과 색상 |
| 연결 상태 | 연결 중·연결됨·연결 끊김·참여 제한 |
| 메시지 목록 | 닉네임, 색상, 메시지, 작성 시각 |
| 메시지 입력 | 텍스트 입력과 전송 버튼 |
| 상태 안내 | 재연결·전송 실패·조합 고갈·이용 제한 안내 |

채팅은 가격 데이터와 시각적으로 구분하고, 사용자 메시지가 공식 정보로 오인되지 않도록 안내한다. 작성자는 색상만으로 구분하지 않는다.

## 4. 사용자 흐름

### 4.1 정상 흐름

1. 이용자가 갈치·고등어·전복 중 하나의 상세 화면에 진입한다.
2. 시스템이 해당 품목의 채팅방에서 사용 가능한 닉네임·색상 조합을 원자적으로 할당한다.
3. 이용자는 할당된 조합과 연결 상태를 확인한다.
4. 기존 표시 범위의 메시지를 조회한다.
5. 텍스트 메시지를 작성해 전송한다.
6. 같은 채팅방의 다른 이용자가 메시지를 실시간으로 수신한다.

최초 표시 범위는 서버가 보존 중인 최근 메시지 50개이며 이전 메시지 추가 조회는 제공하지 않는다.

### 4.2 재연결 흐름

1. 네트워크 또는 서버 상태로 연결이 끊긴다.
2. 서버가 기존 조합을 3분간 예약하고 화면은 연결 끊김·복구 중 상태를 표시한다.
3. 클라이언트가 서버 발급 복원 자격정보로 세션 복원을 요청한다. `localStorage` 식별자만으로 권한을 신뢰하지 않는다.
4. 서버가 세션 소유와 품목별 권한을 검증한다.
5. 3분 이내 복원에 성공하면 기존 조합과 중복 없는 최신 메시지 상태를 복구한다.
6. 예약이 만료되면 신규 참여 절차를 수행한다.

재연결 시도는 1·2·4·8·16·30초 등 최대 30초 지수 백오프를 적용한다.

### 4.3 조합 고갈 흐름

1. 활성·예약 세션이 해당 품목방의 10,000개 조합을 모두 점유하면 신규 채팅 참여를 제한한다.
2. 참여 제한 사유와 자동 재시도 상태를 표시한다.
3. 조합이 반환되면 과도한 반복 요청 없이 자동으로 할당을 다시 시도한다.
4. 조합을 확보하면 정상 연결 상태로 전환한다.

## 5. 기본 기능 요구사항

### FR-CHAT-01. 품목별 채팅방

- 갈치·고등어·전복에 각각 독립된 채팅방을 제공한다.
- 메시지는 `species_id`로 구분한다.
- 한 품목의 메시지를 다른 품목 채팅방에 표시하지 않는다.

### FR-CHAT-02. 인증 없는 참여

- 회원가입과 로그인을 요구하지 않는다.
- 익명 식별자를 영구 회원 계정처럼 표현하지 않는다.
- 개인정보 입력을 기본 참여 조건으로 요구하지 않는다.

### FR-CHAT-03. 메시지 전송

- 연결된 이용자는 허용 범위의 텍스트 메시지를 전송할 수 있다.
- 빈 메시지와 허용 길이를 초과한 메시지는 거부한다.
- 메시지 본문은 최대 300 Unicode 문자다.
- 전송 성공·실패 상태를 확인할 수 있어야 한다.
- 중복 전송을 식별할 수 있는 메시지 ID를 사용한다.

### FR-CHAT-04. 메시지 수신

- 같은 품목 채팅방의 새 메시지를 실시간으로 수신한다.
- 메시지에는 식별자, 품목, 작성자 표시 정보, 본문, 작성 시각이 포함된다.
- 수신 순서를 판단할 수 있는 서버 기준 시각 또는 순서 정보를 사용한다.

### FR-CHAT-05. 연결과 재연결

- 연결 중·연결됨·연결 끊김·참여 제한 상태를 구분한다.
- 연결이 끊기면 자동으로 재연결을 시도한다.
- 자동 재연결은 1·2·4·8·16·30초 등 최대 30초 지수 백오프를 적용한다.
- 재연결 과정에서 같은 메시지를 반복 표시하지 않는다.
- 재연결에 실패해도 가격 차트·Price Insight·최근 이슈 이용을 막지 않는다.

### FR-CHAT-06. 기본 이용 제한

- 메시지는 최대 300 Unicode 문자로 제한한다.
- 서버가 검증한 익명 참여자 세션당 3초 1회 이하, 1분 최대 20회로 제한한다.
- 여러 탭이나 연결을 이용한 제한 우회를 허용하지 않는다.
- 유효하지 않은 입력과 과도한 전송을 거부한다.
- 제한에 걸린 경우 사용자에게 전송 실패 상태를 안내한다.
- 정규화된 금칙어 단어·문구 목록을 서버에서 검사하고 포함 메시지는 거부해 이유를 안내한다.

## 6. 익명 채팅 참여자 식별 및 세션 정책

### FR-CHAT-IDENTITY-01. 랜덤 닉네임·색상 할당

- 최초 채팅 참여 시 서버가 랜덤 닉네임과 색상을 자동 할당한다.
- 닉네임 풀은 500개, 색상 풀은 20개로 구성한다.
- 전체 가능한 조합 수는 10,000개다.
- 닉네임만 같은 경우와 색상만 같은 경우는 허용한다.
- 같은 품목 채팅방에서 `닉네임 + 색상` 조합 전체가 동일한 경우는 허용하지 않는다.
- 서로 다른 품목 채팅방에서는 동일 조합을 허용한다.
- MVP에서는 사용자가 닉네임이나 색상을 수정할 수 없다.
- 조합은 서버에서 중복 검사 및 원자적 할당을 수행한다.

**인수 조건**

- [ ] 최초 참여 시 닉네임과 색상이 자동 할당된다.
- [ ] 사용자가 닉네임을 입력할 필요가 없다.
- [ ] 동일 닉네임과 서로 다른 색상의 동시 사용이 가능하다.
- [ ] 동일 색상과 서로 다른 닉네임의 동시 사용이 가능하다.
- [ ] 같은 품목 채팅방에서 동일 조합이 동시에 할당되지 않는다.
- [ ] 다른 품목 채팅방에서는 동일 조합을 사용할 수 있다.
- [ ] 닉네임·색상 변경 기능이 제공되지 않는다.
- [ ] 두 사용자가 동시에 입장해도 조합 중복이 발생하지 않는다.

### FR-CHAT-IDENTITY-02. 익명 세션 식별

- 사용자 식별에 로그인·회원가입을 요구하지 않는다.
- 서버가 발급한 복원 자격정보로 세션 소유권과 품목별 권한을 검증한다.
- 클라이언트는 `localStorage`에 복원 요청 정보를 보존할 수 있으나 해당 식별자만으로 권한을 신뢰하지 않는다.
- 같은 브라우저의 같은 품목 다중 탭은 하나의 익명 참여자 세션을 공유한다. 탭별 통신 연결은 별도로 관리할 수 있다.
- 닉네임·색상의 소유 여부는 서버 세션 상태를 기준으로 검증한다.
- 클라이언트가 임의로 전달한 닉네임·색상을 그대로 신뢰하지 않는다.
- 품목별 세션과 메시지 전송 권한을 구분한다.
- 익명 식별자는 로그인 계정이나 영구 프로필을 의미하지 않는다.

**인수 조건**

- [ ] 로그인 없이 익명 채팅에 참여할 수 있다.
- [ ] 동일 브라우저의 연결 복구 과정에서 기존 식별자를 사용할 수 있다.
- [ ] 서로 다른 품목의 세션이 혼동되지 않는다.
- [ ] 클라이언트가 조작한 닉네임·색상만으로 기존 참여자의 세션을 탈취할 수 없다.
- [ ] 다른 품목의 참여 권한으로 메시지를 전송할 수 없다.
- [ ] 같은 브라우저·같은 품목의 다중 탭이 하나의 세션과 전송 제한을 공유한다.

### FR-CHAT-SESSION-01. 재연결 및 조합 예약

- 채팅 연결이 끊어지면 서버는 해당 참여자의 조합을 최대 3분간 재연결용으로 예약한다.
- 3분 이내에 동일 세션으로 재연결하면 기존 닉네임·색상을 유지한다.
- 예약 중인 조합은 신규 사용자에게 할당하지 않는다.
- 연결이 복원되면 기존 예약을 활성 세션으로 전환한다.
- 재연결 예약 기간이 만료되면 기존 조합의 예약을 해제한다.
- 예약 만료 후에는 기존 조합 복원을 보장하지 않고 신규 참여 절차를 진행한다.
- 중복 금지 검사는 활성 세션과 아직 만료되지 않은 예약 세션을 대상으로 한다.

**인수 조건**

- [ ] 연결 단절 후 3분 이내 재연결 시 기존 조합을 유지한다.
- [ ] 재연결 예약 중인 조합을 신규 사용자에게 할당하지 않는다.
- [ ] 연결 복원 시 동일 참여자에게 조합이 중복 발급되지 않는다.
- [ ] 예약 기간 만료 후 기존 조합은 재할당 가능 상태가 된다.
- [ ] 예약 기간이 만료된 세션은 기존 조합의 독점 사용을 보장하지 않는다.
- [ ] 네트워크 단절 상태를 사용자에게 표시한다.
- [ ] 재연결 중에도 가격 차트·Price Insight·최근 이슈는 이용할 수 있다.

### FR-CHAT-POOL-01. 조합 풀 고갈 처리

- 동일 품목 채팅방에서 사용 가능한 모든 조합이 점유된 경우 신규 채팅 참여를 일시 제한한다.
- 조합 점유에는 활성 세션과 재연결 예약 세션을 포함한다.
- 참여가 제한된 사용자에게 채팅을 사용할 수 없는 상태를 안내한다.
- 신규 참여자는 사용 가능한 조합이 생기면 자동으로 재시도한다.
- 재시도 과정에서 서버 과부하를 유발하는 무제한 반복 요청은 허용하지 않는다.
- 조합이 확보되면 정상 참여 절차를 완료한다.
- 참여 제한은 채팅에만 적용하며 다른 정보 조회 기능에는 영향을 주지 않는다.

**인수 조건**

- [ ] 동일 품목 채팅방에서 10,000개 조합이 점유되면 신규 참여를 제한한다.
- [ ] 참여 제한 중 채팅 메시지를 전송할 수 없다.
- [ ] 참여 제한 사유를 사용자에게 알린다.
- [ ] 조합이 반환되면 별도 수동 조작 없이 자동으로 참여를 재시도한다.
- [ ] 복수 이용자가 대기하더라도 동일 조합이 중복 할당되지 않는다.
- [ ] 채팅 참여 제한 중 가격 및 분석 화면은 정상 동작한다.

### FR-CHAT-UI-01. 작성자 표시

- 메시지에 작성자의 닉네임, 색상, 작성 시각을 표시한다.
- 닉네임과 색상을 함께 사용해 동일 채팅방의 참여자를 시각적으로 구분한다.
- 색상만으로 작성자를 식별하도록 설계하지 않는다.
- 사용자가 자신의 닉네임이나 색상을 변경하는 UI는 제공하지 않는다.

**인수 조건**

- [ ] 각 메시지에 작성자 닉네임과 색상이 반영된다.
- [ ] 메시지 작성 시각이 표시된다.
- [ ] 동일 닉네임의 서로 다른 색상 참여자를 구분할 수 있다.
- [ ] 작성자 구분에 색상 외 텍스트 정보도 제공된다.

### 기술 설계 시 추가 확인 사항

다음 항목은 본 정책의 확정값을 변경하지 않는 범위에서 기술 설계로 위임한다.

- 서버 발급 복원 자격정보의 생성·보호·폐기 방식
- 비정상 연결 종료 시 3분 예약 시작 시점 판정
- 서버 재시작 및 다중 인스턴스 환경의 세션 복원
- 조합 고갈 시 대기 순서
- 서버 재시작 후 세션·대기 상태 복원 방식
- 500개 닉네임 및 20개 색상 목록과 접근성 검증
- 만료된 익명 세션의 서버 측 정리 방식

## 7. 채팅 데이터 계약

### 7.1 채팅방 및 세션

| 필드 | 의미 |
|---|---|
| `room_id` | 채팅방 식별자 |
| `species_id` | 갈치·고등어·전복 품목 식별자 |
| `anonymous_session_id` | 재연결 요청용 익명 식별자; 서버 검증 필수 |
| `nickname` | 서버가 선택한 500개 풀의 임시 이름 |
| `color_id` | 서버가 선택한 20개 풀의 색상 |
| `connection_status` | 연결 중·연결됨·끊김·참여 제한 |
| `reservation_expires_at` | 서버 측 3분 조합 예약 만료 시각 |

### 7.2 메시지

| 필드 | 의미 |
|---|---|
| `message_id` | 메시지 식별자 |
| `room_id` | 채팅방 식별자 |
| `species_id` | 품목 식별자 |
| `participant_id` | 비영구 참여자 식별자 |
| `nickname` | 작성자 닉네임 |
| `color_id` | 작성자 표시 색상 |
| `content` | 메시지 본문 |
| `created_at` | 서버 기준 작성 시각 |

구체적인 API 경로, 실시간 전송 방식, 토큰과 저장소는 기술 설계에서 결정한다. `anonymous_session_id`만으로 세션 권한을 신뢰하지 않는다.

### 7.3 조회·보존 및 운영 로그

- 최초 조회 메시지는 최근 50개이며 이전 메시지 추가 조회 기능은 제공하지 않는다.
- 메시지는 7일 보존하고 만료 메시지는 일일 배치에서 삭제한다. 7일 초과 메시지는 사용자에게 노출하지 않는다.
- 메시지 본문을 중복 저장하지 않는 최소 운영 이벤트 로그를 30일 보존한다.

| 상태 | 처리 |
|---|---|
| 연결 중 | 채팅 연결 진행 상태 표시, 전송 비활성 |

채팅 오류와 참여 제한은 가격 차트, Price Insight와 최근 이슈 조회에 영향을 주지 않아야 한다.

## 9. 비기능 요구사항

### 9.1 성능

- 품목별 채팅방 500명 동시 참여와 정상 메시지 전달 p95 ≤ 500ms는 출시 필수다.
- 승인된 3초당 1회·분당 20회 제한 내 정상 부하를 시험한다.
- 동일 사용자가 초당 5개 메시지를 시도하는 상황은 별도 비정상 전송 제한 검증 시나리오이며 허용 전송률이 아니다.
- 세부 반복 수와 트래픽 규모는 실제 인프라 사양 확인 후 시험 계획으로 승인받는다.
- 조합 고갈 재시도는 서버 과부하를 유발하지 않도록 제어한다.

### 9.2 안정성

- 조합 할당은 동시 요청에도 중복되지 않도록 원자적으로 처리한다.
- 활성·예약 세션 상태와 예약 만료를 서버에서 일관되게 관리한다.
- 중복 또는 순서가 뒤바뀐 메시지를 식별할 수 있어야 한다.
- 채팅 장애가 읽기 전용 핵심 기능으로 전파되지 않아야 한다.

### 9.3 최소 안전 기준

- 메시지를 실행 가능한 코드나 신뢰된 명령으로 처리하지 않는다.
- 허용하지 않는 입력과 과도한 전송을 제한한다.
- 클라이언트가 전달한 닉네임·색상·세션 식별자를 그대로 신뢰하지 않는다.
- 품목별 세션과 메시지 전송 권한을 서버에서 검증한다.
- 운영상 필요한 메시지 식별 정보와 시각을 추적할 수 있어야 한다.
- 서버 측 정규화 금칙어 검사를 필수로 적용하고 거부 이유를 안내한다.
- 사용자 신고·차단·운영자 삭제 UI와 별도 AI Moderation은 MVP 필수가 아니다.

## 12. 출시 인수 기준

- [ ] 회원가입·로그인 없이 채팅방에 진입할 수 있다.
- [ ] 갈치·고등어·전복 채팅방이 서로 분리된다.
- [ ] 메시지를 전송하고 실시간으로 수신할 수 있다.
- [ ] 서버가 500×20 풀에서 닉네임·색상을 자동 할당하며 사용자가 변경할 수 없다.
- [ ] 같은 품목방의 활성·예약 세션에 동일 조합을 중복 할당하지 않는다.
- [ ] 메시지에서 작성자 닉네임·색상·작성 시각을 확인할 수 있다.
- [ ] 연결 단절 후 3분 이내 유효한 세션 복원 시 기존 조합을 유지한다.
- [ ] 10,000개 조합 점유 시 신규 참여만 제한하고 조합 반환 후 자동 재시도한다.
- [ ] 메시지 길이와 전송 빈도 제한이 작동한다.
- [ ] 최초 최근 50개만 조회되고 7일 초과 메시지는 노출되지 않으며 일일 배치로 삭제된다.
- [ ] 서버 금칙어 검사가 금칙어 포함 메시지를 거부하고 이유를 안내한다.
- [ ] 같은 브라우저·같은 품목의 다중 탭은 하나의 세션을 공유한다.
- [ ] 재연결은 최대 30초 지수 백오프를 적용한다.
- [ ] 메시지 본문 중복 없는 최소 이벤트 로그를 30일 보존한다.
- [ ] 운영 유사 환경에서 품목별 500명과 정상 메시지 전달 p95 ≤ 500ms를 검증한다.
- [ ] 채팅 장애와 참여 제한이 가격·Insight·최근 이슈 조회에 영향을 주지 않는다.
