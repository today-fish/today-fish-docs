# PF-004 최근 이슈

> **핵심 결론:** 오늘의 수산 MVP는 갈치·고등어·전복 관련 뉴스와 공공기관 발표 자료를 모두 하루 1회 수집하며 공공기관 자료를 우선 검토한다. KST 오늘 포함 최근 30개 달력 날짜의 검증된 자료를 최초 5개, 이후 5개씩 제공한다. 추적 파라미터만 제거한 동일 정규화 URL은 중복 제거하되 서로 다른 원문은 유지하며, 새 자료로 과거 Insight를 자동 재분석하지 않는다.
>
> - 문서 상태: DRAFT
> - 상위 문서: [PRD-001 MVP 제품 요구사항](../PRD-001-MVP-제품-요구사항.md)
> - 상위 기능: `CAP-ISSUE`
> - 관련 기능: [PF-003 Price Insight](./PF-003-Price-Insight.md), [PF-005 실시간 채팅](./PF-005-실시간-채팅.md)
> - 관련 정책: [PP-002 AI 분석 운영 정책](../policies/PP-002-AI-분석-운영-정책.md)
> - 적용 플랫폼: 모바일 웹
> - 우선순위: MVP 필수

## 1. 기능 목적

최근 이슈는 사용자가 관심 있는 수산물과 관련해 최근에 발표된 뉴스 기사와 공공기관 자료를 확인할 수 있도록 돕는다.

가격 차트가 가격 변화의 흐름을 보여주고 Price Insight가 해당 변화의 가능한 배경을 설명한다면, 최근 이슈는 관련 자료의 원문을 탐색하는 기능이다.

### 1.1 사용자 목표

1. 관심 수산물과 관련된 최근 뉴스 및 공공기관 자료를 확인한다.
2. 자료의 제목, 출처, 발행일을 확인한다.
3. 관심 있는 자료의 원문으로 이동한다.
4. 최초 표시된 5개 외의 자료를 추가로 탐색한다.
5. 확인된 사실과 AI 해석의 근거가 되는 외부 정보를 직접 살펴본다.

### 1.2 핵심 설계 원칙

- 수산물별 관련 자료를 구분한다.
- 최근 30일 자료를 표시한다.
- 최신 발행일 순으로 정렬한다.
- 최초 5개를 표시한다.
- 동일 URL은 중복 제거한다.
- 같은 사건이라도 서로 다른 기사와 자료는 유지한다.
- 원문 링크를 새 탭에서 연다.
- 기사 내용을 서비스에서 임의로 수정하거나 사실처럼 재구성하지 않는다.
- 최근 이슈 목록과 Price Insight의 과거 근거 조회 정책을 구분한다.

## 3. 화면 구성

### 3.1 위치

최근 이슈는 수산물 상세 화면의 독립적인 정보 영역으로 제공한다.

기본 화면 구성은 다음과 같다.

1. 수산물 상세 화면
2. 가격 차트
3. Price Insight
4. 최근 이슈

최근 이슈의 표시 위치는 위 순서를 기본 설계안으로 한다.

최종 UI 배치는 디자인 단계에서 조정할 수 있으나, 가격 차트 및 Price Insight와 구분 가능한 독립 영역으로 제공해야 한다.

### 3.2 이슈 목록 구성

| 항목 | 설명 |
|---|---|
| 제목 | 뉴스 기사 또는 공공기관 자료 제목 |
| 출처 | 언론사 또는 발행기관 |
| 발행일 | 원문 자료의 발행일 |
| 자료 유형 | 뉴스 또는 공공기관 자료 |
| 원문 링크 | 외부 자료 URL |

### 3.3 목록 표시

- 최초 최대 5개를 표시한다.
- 이슈가 5개 미만이면 존재하는 자료만 표시한다.
- 이슈가 없으면 자료 없음 상태를 표시한다.
- 5개를 초과하는 자료가 있으면 `더보기`를 제공한다.
- 기본 정렬은 발행일 기준 최신순이다.

### 3.4 예시 UI 문구

**영역 제목**

최근 이슈

**자료 없음**

최근 30일 동안 확인된 관련 자료가 없습니다.

**더보기**

더보기

**수집 실패**

최근 이슈를 불러오지 못했습니다.

문구는 UI 초안이며 최종 디자인 단계에서 조정할 수 있다.

## 4. 사용자 흐름

### 4.1 정상 흐름

1. 사용자가 수산물 상세 화면에 진입한다.
2. 시스템은 해당 수산물의 최근 30일 이슈를 조회한다.
3. 자료를 발행일 최신순으로 정렬한다.
4. 최초 5개를 표시한다.
5. 사용자가 특정 자료를 선택한다.
6. 해당 자료의 원문을 새 탭에서 연다.

### 4.2 더보기 흐름

1. 사용자가 최근 이슈 목록을 확인한다.
2. 5개를 초과하는 자료가 존재한다.
3. `더보기` 버튼을 표시한다.
4. 사용자가 `더보기`를 선택한다.
5. 추가 자료를 조회한다.
6. 기존 목록을 유지하면서 추가 자료를 표시한다.

추가 조회는 5개씩 제공하며, 페이지네이션의 `cursor` 또는 `page` 방식은 기술 설계에서 결정한다.

### 4.3 자료가 없는 경우

1. 사용자가 수산물 상세 화면에 진입한다.
2. 최근 30일의 관련 자료를 조회한다.
3. 정상적으로 조회했으나 자료가 없다.
4. `최근 30일 동안 확인된 관련 자료가 없습니다.`에 준하는 안내를 표시한다.

자료가 없는 것과 조회에 실패한 것은 별도 상태로 구분한다.

## 5. 기능 요구사항

### FR-ISSUE-01. 최근 이슈 조회

**요구사항**

사용자가 선택한 수산물의 최근 30일 뉴스 및 공공기관 자료를 제공한다.

**상세 조건**

- 갈치·고등어·전복 각각의 관련 자료를 구분한다.
- 자료의 발행일을 기준으로 최근 30일을 판단한다.
- KST 기준 오늘 D의 D-29 00:00 이상 D+1 00:00 미만을 조회한다.
- 발행일을 확인할 수 없는 자료는 목록에서 제외하고 검토한다.
- 최근 이슈는 상세 화면에서 조회할 수 있다.
- 로그인 없이 이용할 수 있다.
- 선택한 가격 차트 기간과 관계없이 최근 30일 자료를 제공한다.

**인수 조건**

- [ ] 갈치 상세 화면에서 갈치 관련 자료를 조회할 수 있다.
- [ ] 고등어 상세 화면에서 고등어 관련 자료를 조회할 수 있다.
- [ ] 전복 상세 화면에서 전복 관련 자료를 조회할 수 있다.
- [ ] 최근 30일 범위 밖의 자료는 최근 이슈 목록에 표시하지 않는다.
- [ ] 가격 차트에서 과거 기간을 선택해도 최근 이슈 목록의 30일 기준은 변경되지 않는다.

### FR-ISSUE-02. 하루 1회 자동 수집

**요구사항**

뉴스 기사와 공공기관 자료를 하루 1회 자동 수집한다.

**상세 조건**

- 수집 작업은 사용자 조회와 분리한다.
- 수집 결과를 저장한다.
- 원문 URL과 출처 정보를 보존한다.
- 수집 성공 및 실패 상태를 기록한다.
- 중복 자료를 식별한다.
- 사용자 조회 시 저장된 자료를 제공한다.
- 공공기관 자료를 우선 검토하고 뉴스 API는 무료 이용 가능한 제공처를 우선 검토한다.
- 무료 호출 가능 여부와 상업적 사용·AI 분석·본문 저장 권한은 분리해 PoC에서 검증한다.

**인수 조건**

- [ ] 자동 수집 작업을 하루 1회 실행할 수 있다.
- [ ] 수집된 자료를 저장할 수 있다.
- [ ] 사용자 조회마다 외부 뉴스 검색을 필수로 실행하지 않는다.
- [ ] 수집 성공과 실패 여부를 확인할 수 있다.
- [ ] 같은 URL이 중복 수집되어도 중복 표시되지 않는다.

### FR-ISSUE-03. 최신순 정렬

**요구사항**

최근 이슈는 발행일을 기준으로 최신순 정렬한다.

**상세 조건**

- 발행일이 최신인 자료를 먼저 표시한다.
- 수집일과 발행일을 구분한다.
- 오래전에 발행된 자료가 늦게 수집되었다고 최신 기사로 취급하지 않는다.
- 발행 시각이 있으면 최신순으로 정렬하고 동률이면 안정적인 자료 식별자로 정렬한다.
- 없는 발행 시각을 임의 생성하지 않는다.

**인수 조건**

- [ ] 발행일이 더 최근인 자료가 위에 표시된다.
- [ ] 수집일이 최신이라는 이유만으로 오래된 기사가 먼저 표시되지 않는다.
- [ ] 동일한 조회 조건에서 정렬 결과가 불필요하게 달라지지 않는다.

### FR-ISSUE-04. 최초 5개 표시

**요구사항**

최근 이슈 목록의 최초 표시 건수는 최대 5개다.

**상세 조건**

- 자료가 5개 이상이면 최신 5개를 표시한다.
- 자료가 5개 미만이면 존재하는 자료만 표시한다.
- 자료가 없으면 자료 없음 상태를 표시한다.
- 초기 표시 건수를 채우기 위해 오래된 자료를 추가하지 않는다.

**인수 조건**

- [ ] 자료가 12개이면 최초 5개만 표시한다.
- [ ] 자료가 3개이면 3개만 표시한다.
- [ ] 자료가 0개이면 자료 없음 상태를 표시한다.
- [ ] 최근 30일 밖의 자료로 목록을 채우지 않는다.

### FR-ISSUE-05. 더보기

**요구사항**

사용자가 추가 자료를 확인할 수 있도록 `더보기` 기능을 제공한다.

**상세 조건**

- 최초 표시된 5개 외의 자료가 있을 때 더보기를 제공한다.
- 한 번에 5개씩 추가한다.
- 추가 자료는 발행일 최신순을 유지한다.
- 이미 표시된 자료를 다시 중복 표시하지 않는다.
- 모든 자료를 표시한 후에는 추가 조회가 필요하지 않음을 알 수 있어야 한다.

**인수 조건**

- [ ] 자료가 5개를 초과하면 더보기 기능을 사용할 수 있다.
- [ ] 추가 자료가 기존 목록 뒤에 표시된다.
- [ ] 이미 표시된 자료가 중복 추가되지 않는다.
- [ ] 더 이상 조회할 자료가 없으면 더보기 기능이 비활성화되거나 제거된다.

### FR-ISSUE-06. 동일 URL 중복 제거

**요구사항**

같은 원문 URL을 가진 자료는 중복 표시하지 않는다.

**상세 조건**

- URL에서 추적 파라미터만 안전하게 제거하고 의미 있는 파라미터는 보존한다.
- 동일 정규화 URL로 수집된 자료만 하나의 자료로 관리한다.
- 같은 사건이라도 서로 다른 URL을 가진 기사는 유지한다.
- 뉴스와 공공기관 자료가 동일 사건을 다루더라도 서로 다른 원문이면 각각 유지한다.
- URL 정규화 방식은 공통 수집 정책에서 정의한다.

**인수 조건**

- [ ] 같은 URL이 3회 수집되어도 1개 자료로 표시한다.
- [ ] 같은 사건에 대한 서로 다른 URL의 기사 2개는 모두 표시한다.
- [ ] 기사와 공공기관 자료가 같은 사건을 다루더라도 원문 URL이 다르면 각각 유지한다.
- [ ] 자료 제목이 같다는 이유만으로 서로 다른 URL을 임의 병합하지 않는다.
- [ ] 의미 있는 URL 파라미터가 다른 원문을 중복으로 제거하지 않는다.

### FR-ISSUE-07. 출처 정보 표시

**요구사항**

각 이슈에 출처명·제목·발행일·원문 링크를 제공한다.

**상세 조건**

- 출처명은 실제 발행기관 또는 언론사 정보를 사용한다.
- 제목은 원문 자료의 제목을 기준으로 한다.
- 발행일과 수집일을 혼동하지 않는다.
- 원문 링크는 실제 수집된 URL을 사용한다.
- 존재하지 않는 출처나 제목을 생성하지 않는다.

**인수 조건**

- [ ] 이슈별 제목을 확인할 수 있다.
- [ ] 출처명을 확인할 수 있다.
- [ ] 발행일을 확인할 수 있다.
- [ ] 원문 링크를 확인할 수 있다.
- [ ] 출처가 확인되지 않은 자료를 정상적으로 검증된 자료처럼 표시하지 않는다.

### FR-ISSUE-08. 원문 이동

**요구사항**

사용자가 이슈를 선택하면 원문을 새 탭에서 연다.

**상세 조건**

- 외부 링크는 원문 URL을 사용한다.
- 원문은 새 탭에서 연다.
- 현재 서비스 화면은 유지된다.
- 외부 링크에 대한 기본 보안 조치를 적용한다.
- 유효하지 않은 URL을 정상 링크처럼 제공하지 않는다.

**인수 조건**

- [ ] 이슈 선택 시 원문이 새 탭으로 열린다.
- [ ] 기존 오늘의 수산 화면이 유지된다.
- [ ] 원문 URL이 잘못된 내부 경로로 변환되지 않는다.
- [ ] 안전하지 않은 URL 스킴을 허용하지 않는다.

## 6. Price Insight와의 관계

### 6.1 기능 구분

최근 이슈와 Price Insight는 동일한 외부 자료를 활용할 수 있지만, 자료 조회 범위와 목적이 다르다.

| 구분 | 최근 이슈 | Price Insight |
|---|---|---|
| 목적 | 최신 자료 탐색 | 선택 가격 기간의 배경 이해 |
| 시간 범위 | 최근 30일 | 선택한 가격 기간과 관련된 자료 |
| 정렬 기준 | 발행일 최신순 | 관련성 및 분석 근거 기준 |
| 표시 개수 | 최초 5개, 더보기 | 관련 근거 |
| AI 해석 | 필수 아님 | 가능한 해석 제공 |
| 기간 선택 연동 | 연동하지 않음 | 연동함 |

### 6.2 과거 분석을 위한 근거 자료

Price Insight는 선택한 과거 가격 기간에 관련된 자료를 사용할 수 있어야 한다.

예시:

사용자가 2026년 2월의 갈치 가격을 선택한 경우:

- 최근 이슈: 현재 시점 기준 최근 30일의 갈치 자료 표시
- Price Insight: 2026년 2월 가격 흐름과 관련된 근거 자료 사용

따라서 최근 이슈 화면의 30일 필터를 근거 데이터 전체의 보존 기간 또는 분석 조회 제한으로 사용하지 않는다.

### 6.3 자료 저장 및 재사용

- 수집된 자료는 최근 이슈와 Price Insight에서 재사용할 수 있도록 설계한다.
- 출처와 원문 URL을 보존한다.
- 자료의 발행일과 수집일을 구분한다.
- 가격 분석과의 관련성을 식별할 수 있어야 한다.
- 근거 자료의 보존 기간은 PP-002에서 결정한다.
- 신규 자료가 발견되어도 게시된 과거 Insight를 자동 재분석하지 않는다.

## 7. 자료 수집 정책

### 7.1 수집 대상

MVP는 다음 유형의 자료를 대상으로 한다.

1. 뉴스 기사
2. 공공기관 발표 자료

공공기관 자료를 우선 검토한다. 뉴스 API는 무료 이용 가능한 제공처를 우선 검토하되 무료 호출과 상업적 사용·AI 분석·본문 저장 권한은 별개로 검증한다. 실제 제공처와 이용약관은 PoC 후 확정한다.

### 7.2 수집 기본 정보

| 필드 | 설명 |
|---|---|
| source_id | 자료 식별자 |
| source_type | NEWS 또는 PUBLIC_DOCUMENT |
| publisher | 언론사 또는 발행기관 |
| title | 자료 제목 |
| published_at | 발행일 |
| collected_at | 수집일 |
| original_url | 원문 URL |
| related_species | 관련 수산물 |
| collection_status | 수집 상태 |

### 7.3 품목 관련성

자료는 갈치·고등어·전복과의 관련성을 판단할 수 있어야 한다.

- 품목명을 포함한 자료를 후보로 분류할 수 있다.
- 후보 자료는 제목·본문의 직접 관련성을 확인한다.
- 품목명이 등장한다는 이유만으로 가격 변동의 근거라고 확정하지 않는다.
- 품목별로 서로 다른 자료를 조회할 수 있어야 한다.
- 하나의 자료가 여러 품목과 관련될 수 있다.

### 7.4 원문 보존 범위

MVP는 자료의 제목·출처·발행일·원문 URL 등 필요한 메타데이터를 1년간 보존한다.

기사 본문 저장 및 재배포는 해당 출처의 이용 조건을 확인한 범위에서만 수행한다.

원문 본문 보존과 과거 Insight의 장기 출처 추적은 별도 검증한다. 이용 권한이 불명확하면 수집·저장·AI 이용을 보류한다.

자료 수집 방법 및 이용 조건은 PP-002에서 정의한다.

## 8. 최근 30일 조회 정책

### 8.1 기간 기준

최근 이슈는 KST 오늘 D를 포함한 최근 30개 달력 날짜를 조회한다. 경계는 D-29 00:00 KST 이상, D+1 00:00 KST 미만이다. 발행일을 확인할 수 없는 자료는 목록에서 제외하고 검토한다.

### 8.2 시간 정보 구분

| 정보 | 의미 |
|---|---|
| published_at | 자료가 발행된 시점 |
| collected_at | 시스템이 자료를 수집한 시점 |
| updated_at | 시스템 내 자료가 갱신된 시점 |

최근 30일 필터와 최신순 정렬은 발행일을 기준으로 한다.

수집일은 운영 및 갱신 추적에 사용한다.

### 8.3 늦게 수집된 자료

과거에 발행된 자료가 오늘 수집되었다고 해서 최신 자료로 취급하지 않는다.

예시:

- 기사 발행일: 2026-08-01
- 기사 수집일: 2026-10-14

해당 기사는 수집일만을 근거로 최근 이슈 목록에 포함하지 않는다.

다만 과거 Price Insight의 관련 근거로 사용할 가능성은 별도로 판단한다.

## 9. 상태 관리

### 9.1 주요 상태

| 상태 | 설명 | 화면 처리 |
|---|---|---|
| LOADING | 자료 조회 중 | 로딩 상태 표시 |
| READY | 관련 자료 존재 | 목록 표시 |
| EMPTY | 정상 조회했으나 관련 자료 없음 | 자료 없음 안내 |
| ERROR | 목록 조회 실패 | 오류 안내 |
| PARTIAL | 일부 자료만 사용 가능 | 확인된 자료를 표시하고 필요한 상태 안내 |

### 9.2 상태 구분 원칙

- 정상 수집 결과가 없는 것과 API 오류를 구분한다.
- 일부 외부 출처의 수집 실패가 모든 자료의 삭제로 이어지지 않도록 한다.
- 수집 작업의 성공 여부를 기록한다.
- 사용자 조회 오류와 외부 자료 수집 오류를 별도로 추적한다.
- 오래된 저장 자료를 최신 자료로 오인시키지 않는다.

### 9.3 오류 처리

**자료 없음**

"최근 30일 동안 확인된 관련 자료가 없습니다."

**조회 실패**

"최근 이슈를 불러오지 못했습니다."

위 문구는 예시이며 최종 UX 문구는 디자인 검토 후 확정한다.

본 절은 논리적인 데이터 구조 제안이며 실제 REST API 경로를 확정하지 않는다.

### 10.2 목록 응답

| 필드 | 설명 |
|---|---|

추가 조회 건수는 5개다. `cursor`와 `page` 중 구체적인 방식은 기술 설계에서 결정한다.

## 11. 경계 조건 및 예외 처리

### 11.1 최근 30일 자료가 정확히 5개인 경우

- 5개를 모두 표시한다.
- 추가 자료가 없으므로 더보기 버튼을 표시하지 않는다.

### 11.2 최근 30일 자료가 6개인 경우

- 최초 5개를 표시한다.
- 더보기 버튼을 제공한다.
- 더보기 선택 후 나머지 자료를 확인할 수 있다.

### 11.3 동일 URL이 여러 번 수집된 경우

- 동일 정규화 URL의 자료는 하나로 관리한다.
- 중복 수집 시 정상 목록에 같은 자료가 반복 표시되지 않는다.

### 11.4 같은 사건에 여러 기사가 존재하는 경우

- URL이 서로 다르면 각각 표시한다.
- 기사 제목이 비슷하다는 이유로 자동 병합하지 않는다.

### 11.5 자료에 여러 품목이 포함된 경우

- 해당 자료가 여러 품목과 관련될 수 있다.
- 각 품목과의 관련성이 확인된 경우 해당 품목 목록에서 조회할 수 있다.
- 관련성 판단 기준은 PP-002에서 정의한다.

### 11.6 발행일이 없는 경우

- 발행일이 확인되지 않은 자료를 임의 날짜로 보정하지 않는다.
- 최근 이슈 목록에서 제외하고 검토 상태로 관리한다.

### 11.7 자료 원문이 삭제된 경우

- 자료의 메타데이터와 링크 상태를 구분해 관리한다.
- 원문 접근 불가 여부를 확인할 수 있어야 한다.
- 수집 시와 이후 하루 1회 접근 가능 여부를 재검증한다.
- 접근 불가 자료는 목록에서 제외하되 내부 메타데이터와 상태는 유지한다.

### 11.8 외부 수집 작업 실패

- 실패한 수집 작업의 상태를 기록한다.
- 기존 정상 저장 자료를 임의로 삭제하지 않는다.
- 실패한 수집을 정상적으로 자료가 없는 상황과 혼동하지 않는다.
- 해당 출처 단위로 5분·15분·30분 뒤 재시도한다.
- 복구되지 않으면 실패 당일 D부터 D+2까지 일별 재확인하고 운영 검토한다.
- 정상 출처의 수집과 기존 유효 자료 제공은 계속한다.

### 11.9 수집 과정에서 잘못된 URL 발견

- 유효하지 않은 URL을 정상 원문 링크로 표시하지 않는다.
- URL 형식과 허용 스킴을 검증한다.
- 안전하지 않은 링크를 차단한다.

| ISSUE-TC-035 | 원문 접근 불가 | 목록 제외, 내부 메타데이터·상태 유지 |
| ISSUE-TC-036 | 신규 자료 발견 | 게시된 과거 Insight 자동 재분석 없음 |

## 13. 비기능 요구사항

### 13.1 성능

- 사용자 조회 시 원천 뉴스 검색 API 호출을 필수로 요구하지 않는다.
- 사전에 수집·저장한 자료를 조회하도록 설계한다.
- 목록은 최초 5개만 표시한다.
- 추가 자료는 더보기를 통해 조회할 수 있다.
- 실제 응답시간 목표는 PP-003에서 확정한다.

### 13.2 데이터 신뢰성

- 출처와 원문 URL을 보존한다.
- 발행일과 수집일을 구분한다.
- 실제로 확인되지 않은 기사 정보를 생성하지 않는다.
- 동일 URL 중복을 제거한다.
- 자료의 품목 관련성을 확인할 수 있어야 한다.

### 13.3 운영 안정성

- 수집 성공·실패 상태를 기록한다.
- 일부 외부 출처의 장애가 전체 가격 조회 기능에 영향을 주지 않도록 한다.
- 기존 저장 자료를 재사용할 수 있어야 한다.
- 자료 정정 및 삭제에 대한 추적이 가능해야 한다.

### 13.4 저작권 및 이용 조건

- 자료의 원문 링크를 제공한다.
- 기사 전문을 무단으로 재배포하지 않는다.
- 외부 자료의 수집·저장·활용은 이용 조건을 확인한 범위에서 수행한다.
- 원본 자료의 출처를 명확하게 표시한다.

### 13.5 보안

- 안전하지 않은 URL 스킴을 허용하지 않는다.
- 외부 링크에 적절한 보안 속성을 적용한다.
- 외부에서 수집한 콘텐츠를 신뢰된 명령으로 실행하지 않는다.
- 외부 API 인증정보를 사용자에게 노출하지 않는다.

## 15. 출시 인수 기준

### 15.1 기능

- [ ] 갈치·고등어·전복 관련 최근 이슈를 조회할 수 있다.
- [ ] KST 오늘 포함 최근 30개 달력 날짜의 자료를 표시한다.
- [ ] 발행일 최신순으로 정렬한다.
- [ ] 최초 최대 5개를 표시한다.
- [ ] 추가 자료를 5개씩 더보기로 조회할 수 있다.
- [ ] 동일 정규화 URL만 중복 제거한다.
- [ ] 서로 다른 URL의 기사를 같은 사건이라는 이유만으로 병합하지 않는다.
- [ ] 원문을 새 탭에서 열 수 있다.

### 15.2 데이터

- [ ] 뉴스와 공공기관 자료의 출처를 확인할 수 있다.
- [ ] 제목·출처명·발행일·원문 URL을 제공한다.
- [ ] 발행일과 수집일을 구분한다.
- [ ] 정상 수집 후 자료 없음과 수집 실패를 구분한다.
- [ ] 품목별 관련 자료를 정확히 조회한다.
- [ ] 현재 최근 30일 필터가 과거 Price Insight 근거 조회를 제한하지 않는다.
- [ ] 신규 자료가 과거 Insight를 자동 재분석하지 않는다.

### 15.3 운영

- [ ] 하루 1회 자동 수집할 수 있다.
- [ ] 수집 작업의 성공 및 실패를 확인할 수 있다.
- [ ] 사용자 조회 시 저장 자료를 제공할 수 있다.
- [ ] 일부 자료 수집 장애가 가격 차트의 정상 동작에 영향을 주지 않는다.
- [ ] 출처 단위 재시도와 D~D+2 재확인 기록을 확인할 수 있다.
- [ ] 원문 접근 불가 자료는 목록에서 제외하되 내부 상태를 유지한다.
- [ ] 메타데이터를 1년 보존한다.
- [ ] 승인된 성능 및 안정성 기준을 충족한다.
- [ ] 외부 자료의 이용 조건을 검토했다.
