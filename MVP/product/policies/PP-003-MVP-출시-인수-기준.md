# PP-003 MVP 출시 인수 기준

> **핵심 결론:** 오늘의 수산 MVP는 핵심 기능, 데이터 신뢰성, 운영 안정성의 세 가지 조건을 모두 충족해야 출시할 수 있다. 필수 요구사항에 미충족 항목이 있거나 가격·AI 분석의 신뢰성을 보장할 수 없는 경우 출시를 보류한다.

- **문서 상태:** DRAFT
- **상위 문서:** [PRD-001 MVP 제품 요구사항](../PRD-001-MVP-제품-요구사항.md)
- **관련 정책:** [PP-002 AI 분석 운영 정책](./PP-002-AI-분석-운영-정책.md)
- **적용 범위:** 모바일 웹 MVP
- **출시 대상:** 갈치·고등어·전복

---

## 1. 출시 판정 원칙

MVP 출시 여부는 다음 세 영역을 기준으로 판단한다.

| 영역 | 검증 목표 |
|---|---|
| 핵심 기능 | 사용자가 가격과 분석 정보를 정상적으로 조회할 수 있는가? |
| 데이터 신뢰성 | 가격 계산과 AI 분석이 검증된 정책을 준수하는가? |
| 운영 안정성 | 데이터 수집·분석 장애를 감지하고 정상 기능을 유지할 수 있는가? |

### 판정 상태

- `PASS`: 실제 검증을 통해 인수 기준 충족
- `CONDITIONAL_PASS`: 사전에 허용된 예외에 대한 조건부 통과
- `FAIL`: 필수 인수 기준 미충족 또는 출시 차단 결함
- `PENDING`: 기준·시험·증거가 미확정 또는 미완료

`CONDITIONAL_PASS`에는 예외 사유, 위험 평가, 완화 조치, 수정 책임자·기한, 잔여 위험 수용 및 승인 기록이 필요하다. 필수 데이터, 핵심 기능 미구현, 품목별 500명 채팅 성능 미달 또는 중대한 보안 위험을 우회하는 데 사용할 수 없다.

**출시 조건:** `FAIL` 또는 `PENDING`인 필수 항목이 존재하면 출시할 수 없다. 미해결 결함은 조건부 승인했더라도 해결 완료로 표시하지 않는다.

#### 보안 결함 판정

- Critical 결함은 출시를 차단한다.
- High 결함 중 세션 탈취, 개인정보 노출, 인증·권한 우회 등 중대한 피해 가능성이 있는 결함은 출시를 차단한다.
- 나머지 High 결함만 위험 평가·완화 조치·책임자·기한·잔여 위험 수용과 승인 기록을 갖춘 경우 `CONDITIONAL_PASS`로 판단할 수 있다.
- Medium·Low 결함은 실제 영향도에 따라 수정 계획으로 관리한다.
- 미해결 결함은 조건부 승인 여부와 관계없이 해결 완료로 표시하지 않는다.

## 5. 성능 및 운영 지표

다음 목표는 운영 유사 환경에서 측정하고 원본 증빙을 확인한 뒤 판정한다. 실측 자료가 없으므로 현재 상태는 모두 `PENDING`이다.

| 지표 | 목표 | 상태 |
|---|---|---|
| 가격 차트 조회 API | p95 ≤ 500ms | PENDING |
| 저장된 Price Insight 조회 API | p95 ≤ 500ms | PENDING |
| 모바일 LCP | p75 ≤ 2.5초 | PENDING |
| 가격 데이터 수집 성공률 | 연속 7일 ≥ 95% | PENDING |
| AI 분석 생성 성공률 | 미정 | PENDING |
| 원천 가격 제공 확인 후 서비스 반영 | 2시간 이내 | PENDING |
| 신규 기간 Price Insight | 입력 준비 완료 후 2시간 이내 | PENDING |
| 채팅 메시지 전달 | p95 ≤ 500ms | PENDING |
| 채팅 동시 접속 | 품목별 채팅방 500명 | PENDING |
| 채팅 세션 복원 | 연결 단절 후 3분 이내 기존 조합 복원 | PENDING |
| 익명 조합 중복 | 같은 품목방 활성·예약 세션 간 0건 | PENDING |

AI 분석 생성 성공률과 가격 수집 성공률의 정확한 분모·제외 조건은 보류한다. 목표나 산식이 미확정이거나 실측 증빙이 없으면 임의로 통과 처리하지 않는다.

### 5.1 시험 환경 및 증빙

- 출시 합격 기준은 운영 유사 환경에서 측정한 결과다. 로컬 테스트는 보조 검증·회귀 테스트로만 사용한다.
- 스테이징과 운영 서버를 사용하며 성능 시험만을 위한 별도 유료 서버를 요구하지 않는다.
- 스테이징의 서버 사양과 네트워크 조건이 운영과 유사한지 확인한다.
- 실제 서버 사양 확인 후 표본 수, 요청량, 동시 접속자와 반복 횟수를 포함한 시험 계획을 승인받는다.
- 결과에는 환경, 서버 사양, 배포 버전, 시간, 부하 조건, 측정 결과, 실패 원인, 판정과 원본 증빙 경로를 기록한다.
- 품목별 500명 기준 미달 시 비용을 이유로 기준을 낮추지 않고 최적화 후 재검증한다.

## 6. KPI 측정 준비

MVP의 핵심 KPI는 **Price Insight 이용률**이다.

**정의**

수산물 상세 화면 방문자 중 Price Insight를 1회 이상 조회한 익명 이용자의 비율.

**계산식**

Price Insight 이용률(%) =
(Insight 조회 익명 이용자 수 / 상세 화면 방문 익명 이용자 수) × 100

### 인수 조건

- [ ] 상세 화면 방문 이벤트 수집
- [ ] Price Insight 조회 이벤트 수집
- [ ] 중복 조회를 구분할 수 있는 측정 정책 적용
- [ ] 익명 이용자 식별 방식 확정
- [ ] 출시 후 30일 성과 측정 가능
- [ ] 개인정보 수집·보존 정책 검토

KPI 목표값은 출시 전 별도 확정한다.

## 7. 출시 차단 기준

다음 중 하나라도 발생하면 출시를 보류한다.

1. 갈치·고등어·전복 중 필수 가격 조회 기능이 정상 작동하지 않는 경우
2. 가격 집계 산식이 승인된 정책과 다른 경우
3. 결측값을 0원이나 임의 가격으로 표시하는 경우
4. 검증되지 않은 인과관계를 확정적인 원인으로 제공하는 경우
5. AI 분석 장애로 정상 가격 조회가 중단되는 경우
6. 출처가 없는 AI 생성 주장을 확인된 사실로 게시하는 경우
7. 필수 기능의 인수 테스트가 실패한 경우
8. 필수 데이터 품질·보안·운영 기준이 미확정이거나 검증되지 않은 경우
9. 품목별 채팅방이 격리되지 않거나 비로그인 메시지 송수신·재연결이 정상 작동하지 않는 경우
10. 채팅의 최소 Moderation 및 전송 제한 기준이 확정되지 않은 경우
11. 같은 품목방에서 닉네임+색상 조합이 중복 할당되거나 서버가 세션·품목 권한을 검증하지 않는 경우
12. 3분 재연결 예약 또는 조합 고갈 시 신규 참여 제한이 승인된 정책대로 동작하지 않는 경우
13. Critical 또는 중대한 피해 가능성이 있는 High 보안 결함이 미해결인 경우
14. 가격·Insight·LCP·수집·채팅 성능 필수 목표가 미달하거나 운영 유사 환경 증빙이 없는 경우
15. 품목별 채팅방 500명 또는 메시지 전달 p95 500ms 기준을 충족하지 못한 경우
