# PP-002 AI 분석 운영 정책

- **버전:** V1

> **핵심 결론:** Price Insight는 하루 1회 배치에서 각 품목의 최신 완료 월간 1개·반월 1개의 입력 준비 여부를 확인해 분석을 생성·저장한다. 사용자 조회 시 저장된 결과를 제공하며, 게시된 과거 분석은 생성 당시 근거를 보존하는 고정 스냅샷으로 유지한다. 게시 후 오류가 발견되어도 기존 Snapshot은 그대로 유지한다.

- **상태:** 승인
- **상위 문서:** [PRD-001](../PRD-001-MVP-제품-요구사항.md)
- **관련 기능:** [PF-003 Price Insight](../features/PF-003-Price-Insight.md), [PF-004 최근 이슈](../features/PF-004-최근-이슈.md)
- **기존 의사결정:** PD-008, PD-009, PD-010, PD-011, PD-013

---



매일 06:00(Asia/Seoul) 통합 배치에서 품목별 최신 종료 월간 1개와 반월 1개를 새로 생성한다. 초기 3개 품목은 총 6개이며 기존 Snapshot을 수정·덮어쓰거나 가격 부적격 기간을 다른 기간으로 대체하지 않는다. 모든 대상이 검증을 통과해야 함께 게시하고 실패 배치는 공개하지 않는다.

차트 기간 선택은 정확한 `speciesId + granularity + periodStart + periodEnd` Key를 조회한다. 첫 응답의 `publicationBatchId`를 조회 기준점으로 고정하고 그 시점 이하의 최신 정상 게시 이력을 반환한다. 현재 생성 대상에서 빠진 과거 기간도 조회하며, 이력이 없으면 다른 기간 대체 없이 `파악 중`이다. 정상 게시된 Snapshot은 사후 오류 발견 시에도 PUBLISHED 상태와 입력·출력·근거를 그대로 유지한다. MVP는 게시 후 수정·삭제·무효화·정정·수동 재분석을 지원하지 않으며 이전 Snapshot으로 자동 전환하지 않는다.

정상 PRICE_ONLY는 적격 가격은 있지만 적격 Evidence가 없거나 Gemini가 정상적으로 관련 요인 없음을 판단한 경우다. Gemini 호출·출력 검증 실패를 PRICE_ONLY로 처리하지 않는다. 상세 생성·게시·조회 계약은 BE-TECH-SPEC-004 §3·§9·§11을 따른다.

## 1. AI 역할

| 구분 | 역할 |
|---|---|
| 데이터 수집·정리 | 뉴스·공공자료 수집, 중복 제거, 출처 및 기간 관련성 관리 |
| AI 분석·해석 | 가격 데이터와 확인된 사실을 종합하여 가격 변동 가능 요인 도출 |
| 결과 검증 | 근거 확인, 사실·해석 구분, 인과관계 단정 방지 |

- 가격 계산은 기존 가격 데이터 정책을 따르며 AI가 임의 수정하지 않는다.
- 수집된 외부 자료를 신뢰된 시스템 명령으로 취급하지 않는다.
- AI가 생성한 내용을 검증 없이 확인된 사실로 게시하지 않는다.

## 2. 분석 실행 정책

| 항목 | 정책 |
|---|---|
| 실행 주기 | 하루 1회 배치 |
| 실행 방식 | 배치 처리 후 결과 저장 |
| 사용자 조회 | 저장된 결과 반환 |
| 분석 단위 | 품목 + 집계 단위 + 시작일 + 종료일 |
| 집계 단위 | 15일 / 월별 |
| 가능 요인 | 최대 3개, 근거 부족 시 0개 허용 |
| 일일 생성 | 06:00 배치마다 품목별 최신 종료 월간·반월을 새 Snapshot으로 생성 |
| 게시 후 오류 발견 | 기존 PUBLISHED 상태와 Snapshot 불변 유지 |

- 사용자 조회마다 AI 모델을 호출하지 않는다.
- 월별 분석은 해당 월 전체를 별도로 분석한다.
- 과거 기간 분석에는 최근 30일 이전의 관련 자료도 활용한다.
- 현재 일일 생성 대상은 기존 게시본이 있어도 새 Snapshot을 생성한다. 기존 Snapshot은 수정하지 않으며 과거 조회에 사용한다.
- 분석 배치는 하루 1회 실행한다.
- 입력 준비가 확인된 최신 완료 기간의 분석은 준비 완료 후 2시간 이내 생성하는 목표를 적용한다.
- 하루 1회 실행 주기와 입력 준비 후 2시간 목표를 동시에 충족할 수 있는 트리거·실행 시점은 기술 설계에서 검증한다. 두 승인값은 검증 전 임의로 변경하지 않는다.
- 신규 뉴스·공공기관 자료나 단순 가격 변화만으로 현재 생성 대상에서 제외된 오래된 기간의 분석을 자동 재분석하지 않는다.

## 3. 분석 신뢰 정책

| 구분 | 표시 기준 |
|---|---|
| 확인된 사실 | 가격 데이터 또는 검증 가능한 출처로 확인된 정보 |
| 가능한 해석 | 확인된 사실을 근거로 AI가 제시하는 설명 가능성 |
| 파악 중 | 분석 미생성·실패 또는 근거 부족 |

**금지 사항**

- 검증되지 않은 가격 변동 인과관계 단정
- 존재하지 않는 출처·통계·사건 생성
- 품목이나 기간이 관련되지 않은 자료 사용
- 거래량과 가격의 동시 변화를 확정 원인으로 설명
- 세부 상품 매핑이 검증되지 않은 데이터를 동일 상품의 확정 근거로 사용

외부 근거에는 출처명, 문서 제목, 발행일, 원문 URL을 연결한다.

## 4. 분석 결과 관리

분석 결과는 다음 정보를 보존한다.

- 분석 대상: 품목, 집계 단위, 시작일, 종료일
- 분석 내용: 확인된 사실, 가능한 해석, 관련 근거
- 생성 이력: 생성 시각, 갱신 시각, 분석 버전
- 데이터 연결: 사용된 가격 데이터 버전
- 실행 상태: 게시 전 생성·검증의 성공 또는 실패

게시된 과거 분석은 생성 당시 가격 데이터와 근거를 보존하는 고정 스냅샷이다. 조회 기준점 이하 해당 기간 Key의 최신 정상 게시 버전 하나를 선택한다.

정상 게시된 Snapshot은 사후 오류 발견 시에도 PUBLISHED 상태와 입력·출력·근거를 그대로 유지한다. MVP는 게시 후 수정·삭제·무효화·정정·수동 재분석을 지원하지 않으며 이전 Snapshot으로 자동 전환하지 않는다.

기존 게시 Snapshot은 보존한다. 보존 기간은 `PFV-026`의 운영 검토 항목이며 게시 결과 삭제 기능을 뜻하지 않는다.

## 5. 장애 및 예외 처리

| 상황 | 처리 정책 |
|---|---|
| AI 분석 미생성 | AI 해석만 `파악 중` |
| AI 분석 실패 | 가격·확인된 사실 유지, 실패 기록 |
| 근거 부족 | 요인 임의 생성 금지 |
| 출처 검증 실패 | 해당 근거를 확인된 사실로 사용하지 않음 |
| 단순 가격 데이터 변경 | 현재 생성 대상에서 제외된 오래된 기간의 분석 자동 무효화·재분석 금지 |
| 명백한 가격 계산 오류 | 게시 전이면 검증 실패, 게시 후이면 기존 결과 유지 |
| 신규 외부 근거 추가 | 현재 생성 대상에서 제외된 오래된 기간의 분석 자동 재분석 금지 |
| 기존 출처·주장 오류 확인 | 게시 전 검증 실패와 게시 후 불변 보존을 구분 |
| 외부 자료 수집 실패 | 실패 기록, 유효한 기존 자료 보존 |
| 중복 분석 실행 | 동일 결과의 비정상 덮어쓰기 방지 |

가격 데이터와 AI 분석의 상태는 독립적으로 관리한다.

## 6. 운영 및 비용

- 하루 1회 배치 분석을 기본으로 한다.
- 사용자 요청별 실시간 AI 분석을 수행하지 않는다.
- 과거 조회는 해당 Key의 게시 이력을 사용하고, 현재 생성 대상은 매일 새 Snapshot을 생성한다.
- 최신 완료 기간의 입력 준비가 확인되면 같은 배치에서 2시간 이내 생성을 완료한다.
- 게시 후 오류 발견으로 기존 결과를 변경하거나 수동 재분석하지 않는다.
- AI 호출량, 비용, 분석 성공·실패 이력을 기록한다.
- API 인증정보는 서버에서만 관리한다.
