# PD-013 가격 데이터 PoC 적용 원칙

## Status

Accepted

## 배경

`POC-003`은 KAMIS 가격 데이터와 공공데이터포털 정산정보를 이용해 가격 차트, 결측 처리, 품목 코드 매핑의 기술적 구현 가능성을 확인했다.

PoC 결과에는 기술 검증뿐 아니라 최초 제공 품목과 데이터 분류 방식에 관한 제품 판단도 포함되어 있었다. 기존 `PD-009`, `PD-010`, `PD-012`와 역할을 명확히 구분하기 위해 PoC 결과의 적용 범위를 결정한다.

## Decision

### PoC와 제품 결정의 역할

PoC는 구현 가능성과 데이터 특성을 확인하는 근거 문서다. PoC 결과만으로 기존 Accepted 제품 결정을 자동으로 변경하지 않는다.

가격 정책은 `PD-009`, 데이터 신뢰 원칙은 `PD-010`, MVP 품목 선정 기준은 `PD-012`를 Source of Truth로 사용한다.

### 초기 제공 품목

갈치·고등어·전복은 가격 데이터 연속성과 차트 구현을 확인한 **개발 검증 품목**으로 채택한다.

후속 제품 검토에서 다음 기준을 확인했다.

* 생산·출하 데이터 확보 가능성
* 환경 또는 시장 이슈 존재 여부
* 뉴스 및 공식자료 확보 가능성
* Price Insight 가치를 보여주기에 적합한지

검토 결과 갈치·고등어·전복을 MVP **최초 제공 품목**으로 확정한다.

### 대표가격 집계

동일 날짜에 여러 시장 가격이 있으면 시장별 가격을 비교한 뒤 평균을 계산한다.

다음 조건을 먼저 확인한다.

* 동일 품목과 비교 가능한 상품 조건인지
* 시장별 가격 편차가 비정상적으로 크지 않은지
* 냉동 상태, 자연산·양식, 규격 또는 등급이 혼합되지 않았는지
* 수집 오류나 이상치가 없는지

비정상적인 편차나 분류 혼합이 발견되면 단순 평균을 대표가격으로 사용하지 않는다. 이상치 처리 기준은 후속 데이터 품질 기술 문서에서 구체화한다.

### 원산지와 상품 상태 추정

KAMIS 품목명·품종명에 `수입` 또는 `냉동` 표시가 없는 데이터를 국산 또는 생물로 분류하는 규칙은 PoC 단계의 **추정 규칙**으로만 사용한다.

원본 필드와 추정 결과를 별도로 저장하고 다음 원칙을 따른다.

* 추정값을 공식적으로 확인된 상품 속성처럼 표현하지 않는다.
* 사용자에게 노출할 때는 추정 또는 분류 기준을 확인할 수 있게 한다.
* 공식 원산지·상품 상태 정보가 있으면 이를 우선한다.
* 신뢰할 수 없는 분류는 대표가격에서 제외하거나 `분류 확인 필요` 상태로 처리한다.

### 결측값

가격이 없는 기간은 0원이나 보간값으로 대체하지 않는다. 차트의 선을 끊고 데이터 부재, 수집 오류, 비교 조건 불일치 등 확인 가능한 상태를 구분해 표시한다.

## Consequences

* `POC-003`은 기술 검증 결과와 초기 품목 선정 근거를 기록한다.
* 갈치·고등어·전복을 초기 제공 품목으로 사용한다.
* 대표가격 계산 전 데이터 품질 검증 단계가 필요하다.
* 추정 분류에는 원본 데이터와 구분되는 상태 정보가 필요하다.

## Follow-up

* 시장 가격 편차와 이상치 판정 기준을 정의하는 기술 문서 작성
* 원산지·보관 상태 분류의 신뢰도와 사용자 표시 방식 검증
