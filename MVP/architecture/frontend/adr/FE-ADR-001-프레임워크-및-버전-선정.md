# ADR-001. 프론트엔드 프레임워크 및 버전 선정

| 항목      | 내용                          |
| --------- | ----------------------------- |
| 프로젝트  | 오늘의 수산                   |
| 작성일    | 2026-10-23                    |
| 선정 기술 | **Next.js 16.x + React 19.x** |
| 라우터    | App Router                    |

## 1. 핵심 결론

오늘의 수산 프론트엔드 프레임워크로 **Next.js 16.x + React 19.x + App Router**를 선정한다.

**핵심 선정 근거**

- **SEO:** SSR·SSG를 활용하여 검색엔진에 주요 콘텐츠를 HTML로 제공할 수 있다.
- **렌더링 유연성:** 공개 가격 정보와 실시간 상호작용 기능에 서로 다른 렌더링 전략을 적용할 수 있다.
- **호환성:** React 19는 Next.js 16 App Router와 호환되는 안정 메이저 버전이다.
- **유지보수:** Next.js 16은 Active LTS로, 신규 프로젝트에서 이전 Maintenance LTS를 도입할 필요성이 낮다.
- **확장성:** 서버 렌더링, 정적 생성, 클라이언트 렌더링을 서비스 성장에 맞춰 활용할 수 있다.

실제 렌더링 성능과 운영 안정성은 프레임워크 버전만으로 보장되지 않으며 별도로 검증한다.

## 2. 기술 선정 배경 및 요구사항

오늘의 수산은 공공 수산물 가격 데이터를 기반으로 가격 차트, Price Insight, 최근 이슈 및 실시간 채팅을 제공하는 모바일 웹 서비스이다.

실제 사용자 확보와 지속적인 서비스 운영을 목표로 하며, 검색 접근성·사용자 경험·보안·유지보수성을 우선한다.

| 요구사항          | 기술적 고려사항                         |
| ----------------- | --------------------------------------- |
| 검색엔진 유입     | SEO, SSR·SSG 지원                       |
| 모바일 웹 성능    | 초기 로딩, 코드 분할, 캐싱              |
| 가격 차트·Insight | 초기 데이터 제공 및 클라이언트 상호작용 |
| 실시간 채팅       | 클라이언트 상태 관리·WebSocket          |
| 서비스 운영       | 보안 패치, 장애 대응, 유지보수          |
| 운영 비용         | 월 3만 원 이내, 정적 배포 가능성        |

## 3. 기술 조합 비교

2026년 10월 기준 공식 지원 정책과 프로젝트 요구사항을 비교하였다.

| 기술 조합                     | 장점                                        | 단점 및 제약                                   | 판단     |
| ----------------------------- | ------------------------------------------- | ---------------------------------------------- | -------- |
| React 19 + Vite               | 단순한 구조, 빠른 개발 환경, 정적 배포 용이 | 기본 SPA 구성은 SEO 대응을 위한 추가 설계 필요 | 대안     |
| Next.js 14 + React 18         | 기존 라이브러리·레거시 코드 호환성          | Next.js 14 공식 지원 종료                      | 제외     |
| Next.js 15 + React 19         | SSR·SSG 지원, 검증된 운영 사례              | Maintenance LTS, 신규 기능 지원 제한           | 제외     |
| Next.js 16 + React 18         | React 18 기반 코드 활용 가능성              | App Router의 React 요구사항과 부적합           | 제외     |
| **Next.js 16 + React 19**     | **Active LTS, 공식 호환성, 유연한 렌더링**  | **마이그레이션 및 운영 학습 비용**             | **선정** |
| Next.js Canary + React Canary | 신규 기능 사전 활용                         | 안정성·호환성 변경 위험                        | 제외     |

### 3.1 React + Vite를 선택하지 않은 이유

React + Vite는 개발 환경이 단순하고 기존 코드를 재사용하기 유리하다.

다만 오늘의 수산은 수산물 가격·시세 관련 검색 유입이 중요하다. 기본적인 CSR 중심 SPA에서는 검색 가능한 초기 HTML을 제공하기 위해 사전 렌더링 등 별도 구성이 필요하다.

Next.js는 렌더링 전략과 라우팅을 통합적으로 제공하므로 장기적인 서비스 구조에 더 적합하다고 판단하였다.

### 3.2 Next.js 14·15를 선택하지 않은 이유

Next.js 14는 공식 지원이 종료되어 신규 서비스의 보안 및 유지보수 관점에서 부적합하다.

Next.js 15는 Maintenance LTS로 필수 보안 패치와 중요 버그 수정을 지원하지만, 기존 15 기반 시스템을 유지해야 하는 상황이 아니라면 신규 프로젝트에서 선택할 이점이 크지 않다.

**기존 시스템 유지와 신규 프로젝트 도입은 구분한다.** 특별한 의존성 문제가 없다면 Active LTS 버전으로 시작하여 조기 메이저 업그레이드 부담을 줄인다.

### 3.3 React 18을 선택하지 않은 이유

React 18은 기존 생태계의 호환성과 축적된 운영 사례가 장점이다.

그러나 Next.js 16 App Router와의 호환성 및 향후 유지보수를 고려하면 React 19가 적합하다.

React 19는 Actions, `useOptimistic`, `useActionState` 등 비동기 UI 관련 기능도 제공한다. 다만 해당 기능은 React 19 선정의 핵심 이유가 아닌 부가적인 이점으로 평가한다.

## 4. 선정 기술의 장점 및 트레이드오프

| 영역        | 기대 효과                                 | 트레이드오프                                  |
| ----------- | ----------------------------------------- | --------------------------------------------- |
| SEO         | SSR·SSG를 통한 검색 가능한 초기 HTML      | 데이터 갱신 및 캐시 정책 설계                 |
| 렌더링      | 페이지 특성에 맞는 서버·클라이언트 렌더링 | Hydration 및 실행 환경 관리                   |
| 라우팅      | App Router 기반 통합 구조                 | 프레임워크 규칙 학습                          |
| 코드 재사용 | 기존 React 컴포넌트 활용 가능             | Vite 설정·라우팅 코드 이전                    |
| 성능        | 코드 분할·Prefetching 등 최적화 기능      | 실제 성능 측정과 튜닝 필요                    |
| 운영        | 공식 지원과 지속적인 보안 패치            | 서버 기능 사용 시 공격 표면 및 운영 비용 증가 |

**핵심 트레이드오프**

React + Vite보다 구조와 학습 난이도가 복잡해질 수 있지만, 검색 접근성과 렌더링 유연성, 장기 유지보수상의 이점을 위해 이를 수용한다.

## 5. 보안 위험 및 대응

### 5.1 React Server Components 보안 사례

2025년 12월 React Server Components에서 인증 없이 원격 코드 실행이 가능한 취약점 **CVE-2025-55182(CVSS 10.0)**가 공개되었다.

이후 서비스 거부(DoS), 소스코드 노출 취약점도 추가로 발견되어 후속 보안 패치가 필요했다.

| 보안 문제      | 관련 CVE                                       | 위험                     |
| -------------- | ---------------------------------------------- | ------------------------ |
| 원격 코드 실행 | CVE-2025-55182                                 | 서버 임의 코드 실행      |
| 서비스 거부    | CVE-2025-55184, CVE-2025-67779, CVE-2026-23864 | 서비스 중단 및 자원 고갈 |
| 소스코드 노출  | CVE-2025-55183                                 | 서버 측 코드 노출        |

**영향 범위:** 취약한 React Server Components 관련 패키지를 사용하는 환경에 영향을 미쳤으며, 모든 React 클라이언트 애플리케이션이 동일하게 취약했던 것은 아니다.

### 5.2 오늘의 수산 대응 원칙

- React와 Next.js의 공식 보안 공지를 확인하고 취약한 버전을 사용하지 않는다.
- 보안 취약점이 발견되면 실제 영향 범위를 확인한 후 수정된 패치 버전을 적용한다.
- 서버 기능 사용 시 인증·인가, 비밀정보 노출 및 외부 입력 처리를 주의한다.

**최신 버전이라는 이유만으로 안전한 것은 아니며, 검증된 보안 패치를 지속적으로 적용하는 것이 중요하다.**

## 7. 최종 결정

| 항목           | 선정 결과                                      |
| -------------- | ---------------------------------------------- |
| 프레임워크     | **Next.js 16.x**                               |
| UI 라이브러리  | **React 19.x**                                 |
| 라우팅         | **App Router**                                 |
| 세부 패치 버전 | 공식 호환 범위 내 보안 수정이 반영된 안정 버전 |
| 렌더링 전략    | 별도 ADR에서 결정                              |
| 배포 환경      | 별도 ADR에서 결정                              |

Next.js 16과 React 19를 선택한 핵심 이유는 특정 신규 기능이나 단순한 버전 최신성이 아니라 **공식 지원, 프레임워크 호환성, SEO, 렌더링 유연성 및 유지보수성**이다.
