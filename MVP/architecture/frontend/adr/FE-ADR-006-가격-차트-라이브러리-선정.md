| 관련 문서 | FE-ADR-001 프레임워크 선정, FE-ADR-004 디자인 시스템 적용, FE-ADR-005 상태 관리 |

## 1. 핵심 결론

오늘의 수산 MVP의 가격 차트 라이브러리로 **Recharts**를 선정한다. 기존 Figma Make 차트 UI를 가능한 범위에서 재사용하되, 실제 구현 라이브러리와 호환성을 확인한 후 통합한다.

**선정 근거 (3줄)**

1. **생태계:** 비교한 주요 npm 차트 패키지 중 다운로드 규모가 크며 공식 문서·예제·커뮤니티 자료를 참고하기 유리하다.
2. **디자인:** SVG 속성과 React 컴포넌트를 활용해 Figma 기반 색상·축·레이블·툴팁을 맞춤 구현할 수 있다.
3. **요구사항:** 15일·월별 가격 추이와 모바일에서 선택하는 날짜별 정보 툴팁을 구현하기 적합하다.

## 2. 기술 대안 및 npm 다운로드 규모

**측정 기준:** 2026-07-01 ~ 2026-07-31, npm 월간 다운로드 스냅샷. 숫자는 실제 서비스 채택 수가 아닌 *패키지 다운로드 수*이며 CI·자동 설치가 포함된다. **코어 패키지·React 래퍼·모듈 단위가 섞여 있으므로 엄밀한 React 사용률 순위는 아니다.**

| 순위\* | 후보 (집계 패키지)                      |   월간 다운로드 | 장점                          | 단점 및 판단                             |
| -----: | --------------------------------------- | --------------: | ----------------------------- | ---------------------------------------- |
|  **1** | **Recharts (`recharts`)**               | **223,706,484** | React 친화적, SVG·커스텀 툴팁 | 대량 포인트 성능 검토 필요 · **선정**    |
|      2 | Apache ECharts (`echarts`)              |      17,869,308 | 복잡한 차트와 인터랙션에 강함 | 설정 부담이 상대적으로 큼 · 제외         |
|      3 | Chart.js React 래퍼 (`react-chartjs-2`) |      17,372,214 | Canvas 기반 일반 차트에 강함  | 완전한 HTML 툴팁은 추가 연동 · 제외      |
|      4 | Highcharts (`highcharts`)               |      11,002,415 | 풍부한 상용 차트 기능         | 라이선스 조건 확인 필요 · 제외           |
|      5 | visx 모듈 (`@visx/shape`)               |      10,385,838 | 세밀한 시각화 제어            | 차트 조합을 직접 구현할 범위가 큼 · 제외 |
|      6 | ApexCharts (`apexcharts`)               |       8,893,000 | 인터랙션과 다양한 기본 기능   | 현재 MVP 대비 기능 범위가 큼 · 제외      |

\* **비교 대상 패키지 내 다운로드 순위**다. D3·Chart.js 코어 등 모든 시각화 관련 npm 패키지를 망라한 순위가 아니며, 패키지별 집계 단위가 다르다. 숫자는 시점에 따라 바뀌므로 향후 ADR의 의사결정 기록으로만 사용한다.

자료: [React Chart Libraries: Data Visualization Guide (2026)](https://www.sumboard.io/guides/react-chart-libraries) — 해당 기간의 npm 집계표.

## 3. 디자인 및 툴팁 적합성

| 요구사항           | Recharts 적용 방향                                                             |
| ------------------ | ------------------------------------------------------------------------------ |
| 가격 추이          | `LineChart`를 중심으로 15일·월별 전환                                          |
| 디자인 시스템      | 선·축·눈금·레이블에 CSS 변수와 디자인 토큰 반영                                |
| 내부 툴팁          | `<Tooltip content={...} />`에 React 컴포넌트를 제공해 날짜·가격·관측 품질 표시 |
| 모바일 UX          | 터치 선택 동작과 선택 상태 유지를 별도 구현·테스트                             |
| 결측 데이터        | 미관측 값을 실제 가격처럼 보간하거나 임의 표시하지 않음                        |
| Price Insight 연동 | 선택한 기간·날짜 상태를 관련 UI에 전달하되 분석 기준과 불일치하지 않게 검증    |

**주의:** 라이브러리가 툴팁을 지원한다는 사실과, 모바일 터치 시 툴팁을 고정하거나 Price Insight와 동기화하는 사용자 경험이 자동 완성된다는 것은 다르다. 해당 인터랙션은 구현·검증 대상이다.

## 4. 트레이드오프 및 도입 원칙

- React 기반 구성과 높은 스타일 자유도를 얻는 대신, 커스텀 툴팁·터치 인터랙션 구현 및 검증 작업이 필요하다.
- 초기 데이터 규모에는 적합하지만 차트 포인트가 크게 늘어나면 실제 렌더링 성능을 측정한다.
- **기존 Figma Make 차트 코드와 시각적 결과를 우선 보존**하며, 라이브러리 이관으로 인한 불필요한 전면 재작업을 피한다.
- Recharts 버전은 Next.js 16·React 19와 호환되는 안정 버전으로 설치하고 종속성 및 보안 업데이트를 확인한다.

## 5. 기술 회의 주요 Q&A

**Q. npm 다운로드 규모가 큰 라이브러리를 선택할 이유는?**  
A. 예제·질문·해결 자료를 찾기 쉬울 가능성이 높아 1인 개발에서 참고 지표가 된다. 다만 다운로드 수만으로 코드 품질이나 지원 수준을 보장하지는 않는다.

**Q. Figma Make에서 구상한 디자인과 툴팁을 구현할 수 있는가?**  
A. 가능하다. SVG 시각 요소의 속성과 `Tooltip`의 React 커스텀 콘텐츠를 조합한다. 단, 모바일 터치 및 선택 유지 UX는 별도 검증한다.

**Q. 고급 금융 차트 라이브러리가 더 적합하지 않은가?**  
A. MVP 요구사항이 간단한 가격 추이·기간 전환·선택 정보 표시이므로 추가 복잡성을 감수할 필요가 낮다.

## 6. 재검토 조건

- 실제 모바일 터치·툴팁 접근성 요구사항을 충족하지 못하는 경우
- 시계열 포인트 증가로 성능 문제가 관측되는 경우
- 기존 코드 이전 비용이 예상보다 큰 경우
