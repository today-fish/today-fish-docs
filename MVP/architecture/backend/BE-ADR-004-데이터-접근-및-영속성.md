# BE-ADR-004 — 데이터 접근 및 영속성

- **상태:** 승인
- **결정:** 2026-10-29

## 핵심 결론

**Spring Data JPA를 기본으로 사용하고, 복잡한 SQL·대량 데이터 저장 등 명확한 필요가 발생하면 Spring JDBC를 선택적으로 사용한다.**

## 결정

- 도메인 CRUD와 일반 조회는 Spring Data JPA 중심으로 구현한다.
- 복잡한 집계 SQL에는 `JdbcClient`/`JdbcTemplate` 등 Spring JDBC를 선택적으로 활용한다.
- 원천 가격 데이터의 대량 저장이 병목으로 확인될 경우 JDBC Batch를 검토한다.
- JPA와 JDBC가 같은 테이블을 변경할 때 영속성 컨텍스트와 DB 상태의 불일치를 주의한다.
- JPA가 내부적으로 JDBC를 사용하므로 JDBC 병행은 JPA의 일반적인 성능 열세를 전제로 하지 않는다.
- 채팅 메시지는 DB에 저장하지 않는다(기존 채팅 정책 유지).

## 검토한 대안

| 대안 | 고려한 장점 | 주요 부담·제약 | 판단 |
|---|---|---|---|
| Spring Data JPA만 사용 | Entity·Repository 중심으로 개발 단순화 | 복잡한 집계 SQL·대량 쓰기에서 SQL 제어가 불편할 수 있음 | 단독 사용은 비채택 |
| Spring JDBC만 사용 | SQL과 실행 경로를 직접 제어 | 반복적인 매핑·CRUD 코드 증가 | 단독 사용은 비채택 |
| **Spring Data JPA + 필요 시 Spring JDBC** | 일반 도메인 개발 생산성과 특수 집계·배치 SQL 제어를 결합 | 혼용 시 영속성 컨텍스트·트랜잭션 일관성 관리 필요 | **채택** |
| jOOQ 중심 | 복잡한 SQL의 타입 안전성·표현력 | 별도 DSL·코드 생성·버전 및 적용 범위 검토 비용 | 현재 미채택; 고도화 시 재검토 |

## 데이터 관리 원칙

- 정형 공공 API 가격 데이터와 검증된 PDF 추출 결과의 핵심 필드를 관계형 모델로 저장한다.
- 수산물·시장·관측 기간·가격 단계·단위·규격·출처를 구분한다.
- 시장 통합 가격지수는 승인된 집계 규칙에 따라 Java/SQL에서 결정적으로 계산한다. AI로 원천 수치나 일별 관측값을 만들어내지 않는다.
- 필요한 경우 집계 결과를 별도 테이블에 저장해 조회 시 반복 계산을 줄인다.

## 재검토 조건

쿼리 실행 계획·부하 테스트에서 반복적인 성능 문제가 확인될 때 JDBC 사용 범위·인덱스·사전 집계를 우선 재검토한다.
