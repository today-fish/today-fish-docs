# BE-ADR-007 — 가격 수집·PDF 분석·Price Insight 파이프라인

- **상태:** 승인
- **최초 결정일:** 2026-10-29
- **개정일:** 2026-11-05
- **관련 문서:** POC-003, POC-004, POC-005, PD-008, PD-010, PD-011, [BE-TECH-SPEC-001](tech-spec/BE-TECH-SPEC-001-데이터-수집-정규화-검증.md), [BE-TECH-SPEC-002](tech-spec/BE-TECH-SPEC-002-가격-데이터-모델링-및-산지-도매가격-산출.md)

## 핵심 결론

**Spring `@Scheduled` + 경량 Orchestrator + PostgreSQL 실행 상태 관리를 채택한다.** Spring Batch는 초기 도입하지 않는다.

MVP 공공 API 원천은 aT 정산정보와 KMI 유통정보이며, KMI 발간물도 검증 후 가격 근거로 사용할 수 있다. KAMIS는 MVP 수집 대상에서 제외한다. 발간물·기사 수집과 AI 추출은 공공 API 수집과 분리하고, **품목별 유효한 가격 데이터 확보를 Price Insight 생성의 필수 조건**으로 한다.

PDF는 문서 특성에 따라 결정적 파싱 또는 AI 직접 분석을 선택한다. AI는 데이터 추출과 근거 기반 해석을 담당하고, 대표 가격지수는 검증된 Java/SQL 로직으로 산출한다.

## 1. 배경 및 검증 근거

오늘의 수산은 가격 추이뿐 아니라 가격 변화의 배경을 제공하기 위해 공공 API 가격 데이터와 KMI 간행물을 활용한다.

기존 API에서 가격을 확보하기 어려운 광어·우럭 등은 PDF를 대체 원천으로 검토하되, MVP 최초 제공 품목에 자동 포함하지 않는다.

**PoC 결과**

- **POC-004:** KMI·FOC PDF 9종 수집 기술 검증 PASS
- **POC-005:** PDF 9종 × 3회, 총 27회 Gemini 분석
  - 반복 일관성 PASS 9/9
  - API·JSON 검증 PASS 27/27
  - 수치·페이지 대조 PASS 89/89
  - S09 원문 내부 불일치 REVIEW

검증 결과 PDF 직접 분석의 활용 가능성을 확인했다. 다만 모든 문서에 대한 완전한 정확성이 입증된 것은 아니므로, **시장 동향과 변동 맥락 파악에 우선 활용**한다.

## 2. 처리 파이프라인

1. **스케줄링:** 원천별 갱신 주기에 따라 `@Scheduled`가 수집을 트리거한다.
2. **실행 관리:** Orchestrator가 실행 ID, 품목, 기준 기간 및 처리 상태를 관리한다.
3. **독립 수집:** aT 정산정보·KMI 유통정보 API, 발간물 및 기사를 수집 유형별로 분리해 처리한다.
4. **추출·정규화:** API 응답은 원천별 매핑·검증을 수행하고, 발간물은 결정적 파싱 또는 AI 추출로 관측 후보를 만든 뒤 별도로 검증한다.
5. **검증·저장:** 수치, 기간, 단위, 규격, 가격 단계 및 원문 출처를 검증하고 PostgreSQL에 저장한다.
6. **가격 원천 선택:** Resolver가 품목별 유효 가격 데이터를 선택한다. 산지·도매 가격과 서로 다른 기준 원천은 [BE-TECH-SPEC-002](tech-spec/BE-TECH-SPEC-002-가격-데이터-모델링-및-산지-도매가격-산출.md)에 따라 독립 산출하며 무조건 병합하지 않는다.
7. **Insight 생성:** 검증된 가격 데이터와 추가 근거로 Price Insight를 생성한다.
8. **게시:** 생성 결과의 수치·근거·출처를 검증하고, 통과한 결과만 게시한다.

## 3. 데이터 및 생성 정책

- **필수 입력:** 품목별 유효한 가격 데이터(API 또는 PDF)
- **선택 입력:** 품목별 보고서, 전체 수산물 동향 등 추가 설명 근거
- 선택 자료가 누락되어도 확보된 근거가 충분하면 Insight 생성을 허용한다.
- 유효 가격이 없거나 근거가 부족하면 신규 생성을 보류하거나 '파악 중'으로 처리한다.
- 사실과 AI 해석을 구분하며, 원문에 없는 수치나 원인을 임의 생성하지 않는다.
- AI 추출 수치는 검증 없이 대표 가격지수에 사용하지 않는다.
- 검증에 실패한 신규 결과가 기존 정상 게시 결과를 덮어쓰지 않도록 한다.

## 4. 실행 및 신뢰성

- **멱등성:** 원천·품목·기준 기간·문서 버전을 기준으로 중복 처리와 저장을 방지한다.
- **실패 복구:** 타임아웃, 제한적 재시도, Backoff 및 재시작 후 미완료 작업 복구를 지원한다.
- **추적성:** PostgreSQL에 실행 상태, 원천·문서 해시, 검증 결과, 페이지 근거, 모델·프롬프트·스키마 버전을 기록한다.
- **자원 관리:** MVP 인프라 예산을 고려해 PDF·AI 작업 동시성을 제한한다.
- **이용 조건:** PDF 수집 권한과 외부 AI 서비스 전송 허용 여부를 각각 확인한다.

## 5. 검토한 대안

| 영역        | 대안                                   | 판단                                        |
| ----------- | -------------------------------------- | ------------------------------------------- |
| 실행 관리   | `@Scheduled` + 경량 Orchestrator       | **채택**                                    |
| 실행 관리   | Spring Batch                           | 초기 복잡도 대비 이점이 제한적이므로 미채택 |
| 실행 관리   | AWS 관리형 워크플로                    | 운영·비용 복잡도로 초기 미채택              |
| PDF 분석    | 결정적 파싱만 사용                     | 비정형 문서 대응 한계                       |
| PDF 분석    | AI 직접 분석만 사용                    | 검증·비용·재현성 부담                       |
| PDF 분석    | 문서별 파싱·AI 분석 선택               | **채택**                                    |
| 데이터 원천 | 공공 API만 필수                        | 품목 확장에 제약                            |
| 데이터 원천 | API·PDF 모두 성공 필수                 | 부분 실패에 취약                            |
| 데이터 원천 | 품목별 유효 가격 필수 + 추가 근거 선택 | **채택**                                    |

## 6. 결정의 영향

**기대 효과**

- API·PDF 원천의 독립 수집과 부분 실패 대응
- 데이터 부족 품목의 확장 가능성
- AI 분석과 결정적 가격 계산의 책임 분리
- 데이터 출처 및 처리 이력 추적

**감수하는 비용**

- 경량 Orchestrator의 상태·복구 로직 직접 구현
- 원천별 가격 호환성 검증
- PDF·AI 출력 검증 및 버전 관리

작업 규모와 실패 복구 복잡도가 증가하면 Spring Batch 또는 별도 실행 환경 도입을 재검토한다.

AI 실행 구조는 [BE-ADR-008 — AI 실행 아키텍처](BE-ADR-008-AI-실행-아키텍처.md)의 결정에 따른다.
