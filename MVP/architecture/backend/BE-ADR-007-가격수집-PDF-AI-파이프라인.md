# BE-ADR-007 — 가격 수집·PDF 분석·Price Insight 파이프라인

- **상태:** 승인(수집 경로 및 게시 세부 검증 조건)
- **결정:** 2026-10-29

## 핵심 결론

**Spring `@Scheduled` + 경량 Orchestrator + PostgreSQL 실행 상태 관리를 채택한다.** 공공 API와 KMI PDF를 모두 정식 데이터 원천으로 인정하고, **품목별로 유효한 가격 원천을 필수 입력**으로 사용한다. Spring Batch는 초기 도입하지 않는다.

## 배경

기존 API 기반 품목(고등어·갈치·전복)의 가격은 공공데이터 API로 수집한다. 추가 후보인 광어(넙치)·우럭(조피볼락)은 기존 API에서 필요한 가격이 반환되지 않아 KMI 품목별 간행물의 가격 자료를 검토해야 한다. 전체 수산물 동향 PDF도 Insight 설명의 근거가 될 수 있다. **광어·우럭은 MVP 최초 출시 3종에 자동 포함되지 않는다.**

## 처리 단계

1. Scheduler가 원천별 갱신·간행물 발행 주기에 맞춰 작업을 트리거한다.
2. Orchestrator가 공통 실행 ID·품목·기준 기간·상태를 관리한다.
3. **독립 수집:** Spring이 공공 API 데이터를 확보하는 동안 KMI 간행물 수집 작업은 해당 PDF를 확인·다운로드한다(초기 PDF 최대 약 5건 예상).
4. PDF는 가급적 결정적 파싱(텍스트·표 추출) 후 **데이터 수집 AI**가 필요한 필드·문맥을 정형화한다.
5. 양쪽 데이터를 스키마·숫자·기간·규격·가격 단계·단위·원문 출처로 검증하고 PostgreSQL에 저장한다.
6. **품목별 가격 데이터 Resolver**가 유효한 가격 입력을 선택한다. 원천별 시간 해상도·가격 단계가 다르면 하나의 동일 가격지수로 무조건 혼합하지 않는다.
7. **Price Insight AI**는 검증된 가격 데이터와 품목별·전체 동향 자료를 종합하여 근거 기반 설명을 생성한다.
8. 수치·출처·기간·근거를 다시 검증한 결과만 게시하고, 이전 정상 결과를 미검증 결과가 덮어쓰지 않도록 한다.

## 필수·선택 입력 정책

- **필수:** 해당 품목에 대해 유효한 가격 데이터가 확보될 것. 원천은 공공 API일 수도 KMI PDF일 수도 있다.
- **선택:** 품목별 보충 보고서, 전체 수산 유통 동향 보고서 등 설명의 추가 근거.
- 선택 자료 일부/전체 실패 시 수집 종료 조건에 따라 **확보된 근거만으로** Insight를 생성할 수 있고, 누락 사실·분석 기준 시점·한계를 표시한다.
- 유효한 가격 자료가 없거나 가격 검증이 실패하면 신규 가격 Insight 생성을 보류한다.
- 문서에 없는 일별 가격, 공급 원인, 통계 수치를 AI가 임의 생성하지 않는다. 대표 가격지수 계산은 승인된 Java/SQL 로직을 사용한다.

## 실행 및 신뢰성 설계

- 공공 API 수집과 PDF 분석은 독립 작업으로 취급하며, 외부 API에 대해 타임아웃·제한적 재시도·Backoff를 적용한다.
- 동일 기준일·품목·문서의 중복 실행을 방지하고, 수집 레코드는 자연키/유일 제약·Upsert 등으로 멱등성을 확보한다.
- PostgreSQL에 실행 상태·실패 작업·문서 식별자/해시·출처·관측 기간·보고서 페이지·모델/프롬프트/스키마 버전을 기록한다.
- 서버 재시작·스케줄 누락 시 미완료 기간을 확인하고 안전한 재처리 방법을 제공한다.
- EC2 `t2.micro`에서는 작업 동시성을 제한한다. PDF는 초기 순차 처리로 시작하고 AI 호출 처리량을 제한한다.
- KMI 웹사이트의 접근 방식, 실제 간행물 PDF 구조·이용 조건·가격 단위·주기·정확성은 적용 전 확인한다.

## Spring Batch 미도입 근거

현재는 공공 API와 약 5건 이내 PDF를 처리하는 작업으로, Job/Step/Chunk 및 JobRepository 구성의 초기 비용보다 경량 Orchestrator 이점이 크다. 단, 재시작/부분 실패 관리 로직이 비대해지거나 대량 문서 처리·장시간 실행 요구가 생기면 **Spring Batch** 도입을 재검토한다. Batch 도입은 별도 프로세스·서버 분리와 동일한 결정이 아니다.

## 후속 결정(미확정)

- AI 실행 방식: Spring Boot에서 외부 LLM API 직접 호출 vs 별도 Python Worker vs 관리형 워크플로.
- PDF 발행 확인 주기, 문서별 최대 대기 시간, 게시 검증 수준, 실패 시 노출 UI.
- KMI 가격 원천의 가격지수/차트 적용 가능성 및 품목 확대 시점.
