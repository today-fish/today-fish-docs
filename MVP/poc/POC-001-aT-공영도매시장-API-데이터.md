# POC-001 aT 공영도매시장 API 데이터 PoC

## 핵심 결론

한국농수산식품유통공사(aT)의 공영도매시장 API를 이용해
오늘의 수산의 `우럭 가격`을 만들 수 있는지 검증하였다.

API 자체는 정상적으로 동작했고,
수산물 및 조피볼락(우럭)의 표준코드도 존재했다.

그러나 실제 거래 데이터를 조회한 결과
우럭뿐 아니라 주요 어류 데이터가 대부분 날짜에서 거의 존재하지 않았다.

따라서 해당 API는 오늘의 수산의
**Primary Price Source로 사용하지 않는다.**

> **API가 존재하는지보다, 필요한 실제 데이터가 지금도 지속적으로 쌓이고 있는지를 확인하는 것이 더 중요하다.**

---

## 1. 왜 검증했는가?

오늘의 수산에서는 다음과 같은 정보를 제공하려 한다.

- 오늘의 수산물 기준가격
- 가격 변화 차트
- 전월 / 전년 동기 비교
- 시장별 가격 비교
- 가격 변화에 대한 Price Insight

이를 위해서는 특정 수산물의 가격 데이터가
일정한 주기로 계속 축적되는 데이터 소스가 필요하다.

PoC 대표 품목으로 소비자에게 익숙한 **우럭**을 선정하였다.

---

## 2. 검증한 데이터

### 전국 공영도매시장 실시간 경매정보

- 제공기관: 한국농수산식품유통공사(aT)
- Service: `katRealTime2`
- Operation: `trades2`
- 주요 데이터:
  - 거래일자
  - 도매시장
  - 품목
  - 원산지
  - 낙찰가격
  - 거래량
  - 단위

### 농축수산물 표준코드

수산물의 품목과 상태를 확인하기 위해 함께 사용하였다.

우럭으로 일반적으로 유통되는 `조피볼락`의 코드는 다음과 같이 확인하였다.

| 상태 | 대분류 | 중분류 | 소분류 |
|---|---|---|---|
| 활 | 61 활 해면어류 | 43 볼락 | 06 조피볼락 |
| 신선 | 71 신선 해면어류 | 43 볼락 | 06 조피볼락 |
| 냉동 | 81 냉동 해면어류 | 43 볼락 | 06 조피볼락 |

즉, **우럭의 품목코드가 없는 문제는 아니었다.**

---

## 3. PoC 진행 과정

### Step 1. API 정상 동작 확인

2026-10-06 전체 거래 데이터를 조회하였다.

결과:

```text
resultCode = 0
resultMsg = 정상
totalCount = 120,947
```
약 12만 건의 거래가 존재했고
농산물 데이터가 정상적으로 반환되었다.

→ API 자체는 정상

### Step 2. 우럭 표준코드 확인

표준코드 API를 통해 다음 코드를 확인하였다.
```
61 / 43 / 06
활 해면어류 / 볼락 / 조피볼락
```
신선·냉동 상태의 조피볼락 코드 역시 존재하였다.

→ 품목코드 존재

### Step 3. 실제 우럭 거래 조회

활 / 신선 / 냉동 조피볼락을 최근 7일간 조회하였다.
```
2026-09-30 ~ 2026-10-06
```
결과:
```
활 조피볼락    0건
신선 조피볼락  0건
냉동 조피볼락  0건
```
→ 코드는 있지만 실제 거래 데이터가 확인되지 않음

### Step 4. 우럭만의 문제인지 확인

조건을 넓혀 활 해면어류(61) 전체를 조회하였다.
```
2026-06-01 : 0건
2026-07-01 : 0건
2026-08-01 : 0건
2026-09-01 : 0건
2026-09-15 : 2건
2026-09-30 : 0건
```
→ 우럭만의 문제가 아니라 주요 활어 데이터 자체가 매우 부족

### Step 5. 수산물 전체 분류 확인

2026-10-06 기준 주요 수산물 대분류를 조회하였다.

확인된 예:
```
76 신선 해조류 : 117건
93 수산가공    : 20건
```
반면 다음 분류는 0건이었다.
```
61 활 해면어류
71 신선 해면어류
81 냉동 해면어류
```
→ 수산물 데이터가 완전히 없는 것은 아니지만
오늘의 수산이 필요로 하는 주요 생선 데이터의 커버리지가 부족

## 4. 최종 판단
전국 공영도매시장 실시간 경매정보

**NO-GO — Primary Price Source**

이유:
```
API 자체는 정상
표준코드 존재
일부 수산물 데이터 존재
하지만 우럭 거래 데이터가 거의 없음
주요 어류 데이터도 대부분 날짜에서 없음
일별 가격 시계열 구축이 어려움
대표가격 및 전년 동기 비교가 어려움
```

따라서 가격 차트와 기준가격의 핵심 데이터 소스로 사용하지 않는다.

농축수산물 표준코드

Reference 용도로만 활용 가능

가격 데이터 소스로는 사용할 수 없지만
외부기관 품목 Mapping 시 참고할 수 있다.

## 5. 이번 PoC에서 얻은 핵심 인사이트
### ① API 존재 ≠ 서비스 사용 가능

API가 정상 응답한다고 해서
서비스에서 사용할 수 있는 데이터라는 의미는 아니다.

반드시 다음을 확인해야 한다.

API 존재
→ 호출 가능
→ 품목 존재
→ 실제 데이터 존재
→ 최근 데이터 갱신
→ 데이터 연속성
→ 충분한 데이터량
→ 서비스 활용 가능

### ② 표준코드 존재 ≠ 실제 데이터 존재

조피볼락 코드가 존재했지만
실제 거래 데이터는 거의 없었다.

따라서 코드 목록만 보고 데이터 확보 가능성을 판단하면 안 된다.

### ③ 외부기관의 품목코드에 종속되면 안 된다

기관마다 수산물 이름과 코드체계가 다를 수 있다.

```
예:
오늘의 수산   : 우럭
aT            : 조피볼락
KMI           : 기관별 우럭 코드
KAMIS         : 기관별 품목코드
```
따라서 오늘의 수산에서는 자체 품목 기준을 가지고
기관별 품목코드를 Mapping하는 구조가 필요하다.

```
FISH_0001
우럭 / 조피볼락

        ↑
   ┌────┼────┐
  aT   KMI  KAMIS
```
