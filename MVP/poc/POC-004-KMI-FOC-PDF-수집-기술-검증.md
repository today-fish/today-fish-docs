## 2. 구현 및 검증 방식

### 2.1. 수집 흐름

```text
SOURCES 배열 순회
  └─ switch (platform)
       ├─ FOC: findLatestFoc(source)
       │    목록 페이지 GET → #cms_trebook_article .tbListA li.year.first
       │    → li.month > a[href] 중 발행연월이 최신인 PDF URL 선택
       └─ KMI: findLatestKmi(source)
            rbsIdx=394 목록 GET → 최신 상세 view.do 링크 선택
            → 상세 페이지 GET → .bbsHead 내 download.do PDF 링크 추출
  → 공통 downloadPdf(url, target)
  → PDF %PDF- 시그니처 확인
  → PDFBox로 페이지 수 조회
  → CLI 표에 성공/실패·발행일·파일명·MiB·시간 출력
```

- 언어/구성: Java CLI, JDK `HttpClient`, `jsoup`, Apache PDFBox, Gradle Wrapper.
- 파일 처리: 입력 스트림을 64KiB 버퍼로 임시 파일에 기록한 후 대상 경로로 이동. PDF 전체를 애플리케이션 Heap에 읽어들이는 방식은 사용하지 않음.
- 파일 크기 제한: **50 MiB로 확장 예정**(`50L * 1024 * 1024` = 52,428,800 bytes). **이번 실측은 40 MiB 제한으로 실행한 결과**이며, 50 MiB 설정 변경 후의 재실행은 아직 하지 않았다. 최대 관측 크기는 새우 PDF 37.13 MiB.
- 실행 방식: 단일 프로세스에서 순차 조회·다운로드; 대상 간 300ms 대기.
- 출력 파일: `results/pdf/Sxx-<발행일 또는 발행월>-<원본·생성 파일명>.pdf`.
- 검증: HTTP 응답/다운로드 성공, 파일 `%PDF-` 시그니처, PDFBox 파싱 및 페이지 개수 조회. **해시 검증·원문 내용 정확성 검증은 수행하지 않음.**

### 2.2. 플랫폼별 차이

**FOC**는 목록에 연도별 월간 PDF 링크가 직접 포함된다. 광어의 HTML 사례에서 `li.year.first` 아래의 `li.month > a[href]` 구조를 확인하였고, 다른 FOC 수집 대상에도 동일한 탐색 로직을 적용해 성공했다. 종자관측 우럭은 실제 사이트 메뉴에 따라 `cs_category=5`를 사용했다.

**KMI**는 목록 페이지에서 `view.do?rbsIdx=394&idx=...` 상세 링크를 찾고, 상세 게시물의 `download.do` 링크를 추출한다. 이번 실행에서는 `idx=31`, 발행일 `2026-10-28`을 선택했다. 게시판 첫 링크를 최신 게시물로 취급하는 구현이므로 **목록 정렬 변경에 대한 내구성은 미검증**이다.

### 2.3. 기본 URL·PDF URL 패턴 및 정규화 절차

**정규화의 의미:** HTML에서 받은 상대 경로(`href`)를 그 페이지의 URL을 기준으로 **절대 HTTPS URL로 변환**하고, 요청 대상 호스트·경로·식별자와 확장자(FOC) 또는 다운로드 엔드포인트(KMI)를 검증한다. 여기서 정규화는 **PDF 내부 텍스트/가격·단위 정규화가 아니다.** 파일명과 발행일도 별도 메타데이터로 관리한다.

| 구분            | FOC 수산물수급정보센터                                                     | KMI 한국해양수산개발원                                                                |
| --------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 기본 URL        | `https://www.foc.re.kr`                                                    | `https://www.kmi.re.kr`                                                               |
| 목록 URL 패턴   | `/web/obsbook/list.do?rbsIdx={rbsIdx}&cs_category={category}`              | `/web/trebook/list.do?rbsIdx=394`                                                     |
| 게시글 상세     | 별도 상세 페이지 접근 불필요                                               | `/web/trebook/view.do?rbsIdx=394&idx={idx}`                                           |
| PDF 링크 패턴   | `/rbs/data/files/obsbook/{dir}/{file}.pdf`                                 | `/web/trebook/download.do?rbsIdx=394&idx={idx}&...&itemId=saved_pdf_file_name`        |
| 탐색 선택자     | `#cms_trebook_article .tbListA li.year.first li.month > a[href]`           | 목록의 `a[href*='view.do']` → 상세 `.bbsHead a[href*='download.do'][href*='itemId=']` |
| 최신 자료 판단  | 월 링크의 `YYYY년 MM월` 중 가장 큰 발행연월 (현 PoC는 첫 연도 블록만 탐색) | 목록에서 **첫 번째 유효 상세 링크** (현재 구현 가정)                                  |
| 다운로드 파일명 | 원본 URL 경로의 마지막 `.pdf` 파일명                                       | 서버 응답의 실제 원본 파일명은 확인하지 않음; PoC에서 `kmi-394-{idx}.pdf` 생성        |

**FOC 변환 예시 — 2026년 10월 광어**

```text
base = https://www.foc.re.kr
list = /web/obsbook/list.do?rbsIdx=37&cs_category=7
HTML: li.year.first → li.month > a[href]
anchor text = + 2026년 10월
href = /rbs/data/files/obsbook/1/202610121414171.pdf
↓ 현재 목록 URL 기준 상대 링크 절대화(anchor.absUrl("href"))
pdf = https://www.foc.re.kr/rbs/data/files/obsbook/1/202610121414171.pdf
period = 2026-10
filename = 202610121414171.pdf
stored = S03-2026-10-202610121414171.pdf
```

FOC는 8개 시리즈를 `rbsIdx`와 `cs_category` 조합으로 순회한다. 유효한 `https://www.foc.re.kr` 호스트, `/rbs/data/files/obsbook/` 접두 경로 및 `.pdf` 확장자를 확인한 후 발행월을 비교한다. 동일 연도의 월별 링크가 반드시 12개 존재한다고 가정하지 않는다.

**KMI 변환 예시 — 국제공급망리스크 모니터링 Vol.31**

```text
base = https://www.kmi.re.kr
list = /web/trebook/list.do?rbsIdx=394
HTML 목록의 상대 링크 = view.do?rbsIdx=394&idx=31
↓ 목록 URL 기준 절대화
detail = https://www.kmi.re.kr/web/trebook/view.do?rbsIdx=394&idx=31
상세 HTML: .bbsHead 내 'PDF Download' 앵커
href = download.do?rbsIdx=394&idx=31&_o_f=...&_o_o=...&itemId=saved_pdf_file_name
↓ 상세 URL 기준 절대화
pdf = https://www.kmi.re.kr/web/trebook/download.do?rbsIdx=394&idx=31&_o_f=...&_o_o=...&itemId=saved_pdf_file_name
published_at = 2026-10-28  (상세 페이지의 '발행일')
filename = kmi-394-31.pdf  (PoC 생성 이름)
stored = S02-2026-10-28-kmi-394-31.pdf
```

KMI의 `_o_f`, `_o_o`는 서버가 HTML에 제공한 첨부파일 파라미터를 **수정·재인코딩·추측하지 않고 그대로 사용**한다. `URI`를 통한 절대화 후에도 쿼리 문자열의 `%25` 등 인코딩은 유지되어야 한다.

PDF 주소를 `idx`만으로 새로 만들어서는 안 된다. 허용 다운로드는 `https`, `www.kmi.re.kr`, `/web/trebook/download.do`, `rbsIdx=394`, `idx`, `itemId=saved_pdf_file_name` 조건으로 제한한다.

두 플랫폼 모두 다운로드 응답의 최종 URL(리다이렉트 후), HTTP 200, `Content-Length`와 누적 바이트, 파일 선두 `%PDF-` 및 PDFBox 파싱을 확인한다. 단, **HTTP 200과 PDF 파싱 성공은 재이용 권한의 증거가 아니다.**

### 2.4. 다운로드 파일 크기 상한: 50 MiB

PoC의 파일 크기 제한은 **40 MiB → 50 MiB**로 확장하는 것으로 정한다. `50 MiB = 52,428,800 bytes`이며, 50 MB(50,000,000 bytes)와 구별한다.

```java
private static final long MAX_BYTES = 50L * 1024 * 1024;
```

- 서버가 `Content-Length`를 제공하면 요청 수신 직후 상한을 검사한다.
- `Content-Length`가 누락되거나 실제와 다른 경우를 대비하여 64 KiB 스트리밍 과정에서도 **누적 다운로드 바이트**를 검사한다.
- 상한 초과, 비정상 PDF, 다운로드 실패 시 임시 파일을 정리한다.
- **기존 9/9 PASS 로그는 40 MiB 설정의 실측 결과다.** 50 MiB 변경은 아직 재실행으로 검증되지 않았으므로 별개 항목으로 표시한다.
- 50 MiB는 **크롤러의 로컬 파일 제한**이며 Gemini Files API의 허용 크기나 외부 전송 권한을 뜻하지 않는다.

### 2.5. 공공누리 제4유형과 수집 제외 정책

**공공누리(KOGL) 제4유형**의 이용 조건은 **① 출처표시 + ② 상업적 이용금지 + ③ 변경금지**다. 한국저작권위원회의 유형 안내에 따르면 출처·저작권자를 표시해야 하며, 비영리 목적 이용만 허용되고 저작물의 변경 및 2차적 저작물 작성은 제한된다. 별도 허락을 받은 경우 이용 범위가 달라질 수 있다.

- **이번 PoC의 제외 대상:** KMI 주간 주요수산물 수급리포트 `rbsIdx=387`은 제공된 상세 페이지에서 `공공누리 제4유형`과 해당 표시 이미지가 확인되었다. 이에 따라 **소스 배열에서 제외하고, 목록 조회·상세 조회·파일 다운로드·AI 전송을 실시하지 않았다.**
- **포함 대상:** KMI `rbsIdx=394` 국제공급망리스크 보고서의 제공된 상세 HTML에는 제4유형 표시가 확인되지 않았다. 이번 PoC에서는 다운로드만 검증했으며, **제4유형 표시 부재가 상업적 재이용이나 Gemini 외부 전송의 허가를 입증하는 것은 아니다.**
- **FOC:** 8개 PDF의 다운로드 기술 성공은 해당 파일의 재배포, 2차적 가공, AI 전송 이용 조건까지 검증한 결과가 아니다.
- **운영 원칙:** 제4유형으로 확인된 자료는 현재 정책상 아예 수집 대상에 추가하지 않는다. 표시가 없거나 불명확한 문서에 대해서도 외부 AI 전송·재이용을 자동 허용하지 않으며, 해당 문서 또는 제공기관의 이용 조건을 별도 확인한다. 저작권 예외·허가 여부는 개별 사안에 따라 판단해야 한다.

### 3.2. 결과 해석

- **성공률:** 이번 실행에서 9/9건(100%). 반복 실행 성공률이나 장기 가용성 100%를 뜻하지 않는다.
- **다운로드 소요 시간:** 합산 18.981초. 소스별 전체 시간 합산 26.792초는 조회·PDF 검사 등이 포함된 값이며, `BUILD SUCCESSFUL`로 표시된 Gradle 실행 약 27초와는 측정 범위가 다르다.
- **큰 PDF:** 새우(37.13 MiB·6쪽), 전복(30.35 MiB·8쪽). 향후 상한을 50 MiB로 높여 여유를 확보하되, 이번 실측값은 변경 전 40 MiB 설정에서 측정됐다.
- **페이지와 파일 크기는 비례하지 않음:** 대중성 어종은 28쪽·4.37MiB, 새우는 6쪽·37.13MiB. Gemini 토큰량을 파일 크기만으로 환산하지 않는다.
- **발행월 ≠ 업로드 파일명에 포함된 날짜:** 종자관측 우럭은 발행월이 `2026-06`이나 파일명에는 `20260915`가 포함된다. 발행 정보는 링크의 문구/게시물 메타데이터로 별도 저장해야 한다.

## 5. 후속 검증과 설계 반영

1. **Gemini 벤치마크:** 각 PDF의 이용 조건을 먼저 확인하고, 외부 AI 전송이 허용된 대상에 한해서 Files API 업로드 시간, 입력/출력 토큰, 모델 응답 시간, 추출 정확도를 실측한다. 한 PDF의 1회 측정치를 전체 자료에 일반화하지 않는다.
2. **신규 발행·수정 감지:** FOC 발행연월 및 실제 PDF URL, KMI 게시물 `idx`/첨부 URL, 파일 해시를 분리해 추적한다. 발행되지 않은 기간은 오류로 간주하지 않는다.
3. **크기 제한 변경:** 후속 크롤러 코드에서 `MAX_BYTES`를 **50 MiB**로 확장한다. 다운로드 전 `Content-Length`와 스트리밍 중 누적 바이트 모두 이 상한으로 검사하고, 변경 후 9개 문서 재실행으로 검증한다. 임시 저장공간·타임아웃 및 Gemini 업로드의 별도 제약은 추가로 확인한다.
4. **운영 안정성:** 일정 기간의 반복 조회, 서버 오류, 응답 지연, 부분 다운로드, 중복 실행에 대한 재시도/멱등성 검증이 필요하다.
5. **아키텍처 반영:** [`BE-ADR-007`](../architecture/backend/BE-ADR-007-가격수집-PDF-AI-파이프라인.md)의 PDF 초기 최대 약 5건 예상과 이번 9개 대상 목록의 차이를 다음 ADR 갱신 시 검토한다. 이번 결과만으로 병렬성·운영 스케줄을 확정하지 않는다.
