## 1. PoC 목적과 진행 과정

### 1.1. PoC란?

PoC(Proof of Concept)는 서비스를 본격적으로 개발하기 전에 **우리가 생각한 기능을 실제로 만들 수 있는지 확인하는 실험**이다.

오늘의 수산에서는 다음 질문을 검증했다.

1. 수산물의 과거 가격을 API로 가져올 수 있을까?
2. 여러 시장의 가격으로 평균가격을 계산할 수 있을까?
3. 1년치 가격 그래프를 만들 수 있을까?
4. 가격이 없는 기간은 얼마나 있을까?
5. 거래량 데이터도 가져와 가격과 함께 분석할 수 있을까?

### 1.2. 진행 과정

1. KAMIS 가격 API를 호출해 일별 수산물 가격 수집
2. 시장별 가격을 kg 단위로 통일
3. 같은 날짜의 여러 시장 가격을 단순 평균
4. 15일·월별 평균가격 계산
5. 1년치 가격 차트 생성 및 결측값 조사
6. 공공데이터포털 정산정보 API를 호출해 거래량·거래금액 확인
7. 서로 다른 기관의 품목 코드 연결 가능성 검증

가격 데이터는 **2025년 10월 1일~2026년 9월 30일**을 대상으로 검증했다.

정산정보는 **2026년 7월 일부 날짜와 시장**에서 탐색했으므로, 가격과 거래량을 1년 전체에 걸쳐 연결한 것은 아니다.

## 2. 개발 검증 품목 선정 결과

PoC에서는 여러 수산물의 1년치 가격 데이터를 비교한 뒤 **갈치·고등어·전복**을 개발 검증 품목으로 선정했다.

이 세 품목은 가격 데이터 연속성과 차트 구현을 검증한 대상이다. 후속 제품 검토 결과 `PD-012`의 초기 제공 품목으로 확정했다.

| 품목 | KAMIS 코드 | 가격이 존재한 15일 구간 | 실제 가격 관측일 | 선정 이유 |
|---|---|---:|---:|---|
| 갈치 | `613/01` | 24/24 | 241일 | 1년 동안 모든 반월 구간에 가격 존재 |
| 고등어 | `611/01` | 21/24 | 199일 | 소비자 관심도가 높고 활용성이 큼 |
| 전복 | `653/00` | 24/24 | 241일 | 1년 동안 모든 반월 구간에 가격 존재 |

**여기서 24/24는 무엇일까?**

1년을 상반기와 하반기로 나누면 총 24개 구간이 된다.

- 1월 1~15일: 첫 번째 구간
- 1월 16~31일: 두 번째 구간
- ...
- 12월 16~31일: 마지막 구간

`24/24`는 **모든 구간에 최소 하루 이상의 가격 기록이 있다**는 뜻이다.

365일 모두 가격이 존재한다는 뜻은 아니다.


### 2.1. 대표 가격의 기준

PoC 차트에서는 **국산 생물로 추정한 수산물의 평균가격**을 사용했다.

KAMIS에는 같은 수산물이라도 `생선`, `냉동`, `국산(신선 냉장)`, `수입산(냉동)` 등 여러 품종이 존재한다.

PoC에서는 데이터를 일관되게 분류하기 위해 다음과 같은 기준을 적용했다.

#### ① 국산과 수입산 구분

- 품목명 또는 품종명에 **'수입'이라는 표시가 있으면 수입산**으로 분류한다.
- **'수입'이라는 표시가 없으면 국산**으로 간주한다.
- 수입산으로 분류된 가격은 대표 가격 차트에서 제외하고, Price Insight 분석에만 활용한다.

#### ② 생물과 냉동 구분

- 품목명 또는 품종명에 **'냉동'이라는 표시가 있으면 냉동 수산물**로 분류한다.
- **'냉동'이라는 표시가 없으면 생물**로 간주한다.
- '생선', '활어', '신선', '냉장'도 생물에 포함한다.
- 건조·건어류는 냉동 여부와 관계없이 생물에서 제외한다.

#### ③ 실제 분류 예시

| KAMIS 품종명 | 원산지 분류 | 상태 분류 | 대표 차트 |
|---|---|---|---|
| 생선 | 국산 간주 | 생물 | 포함 |
| 국산(신선 냉장) | 국산 | 생물 | 포함 |
| 연근해(신선 냉장) | 국산 간주 | 생물 | 포함 |
| 냉동 | 국산 간주 | 냉동 | 제외 |
| 국산(냉동) | 국산 | 냉동 | 제외 |
| 수입산(냉동) | 수입산 | 냉동 | 제외 |
| 수입산(신선) | 수입산 | 생물 | 제외 |
| 마른오징어 | 국산 간주 | 건조 | 제외 |

#### ④ 이러한 기준을 적용한 이유

KAMIS에서는 수입산이나 냉동 상품을 별도로 구분한 품종명이 존재한다.

따라서 PoC에서는 **별도의 수입·냉동 표시가 없다면 국산 생물로 취급하는 단순한 분류 규칙**을 채택했다.

예를 들어 KAMIS의 `갈치/생선`은 수입이나 냉동이라는 표시가 없기 때문에 국산 생물 가격으로 분류한다.

이 규칙을 적용하면 품종별 원산지와 보관 상태를 일일이 수작업으로 확인하지 않고도 데이터를 자동으로 분류할 수 있다.

**주의사항**

이 규칙은 PoC 내부 계산에 사용한 **데이터 분류 가정**이며, 확정된 상품 속성이나 사용자 표시 정책이 아니다.

수입 표시가 없다는 사실만으로 실제 원산지가 국산임을 증명할 수는 없으며, 냉동 표시가 없다는 사실만으로 모든 상품이 실제 생물이라는 사실이 보장되는 것도 아니다.

따라서 데이터베이스에는 원래 KAMIS 품종명과 서비스에서 추정한 원산지·상태 분류를 함께 저장하고, 관측값과 추정값을 구분한다.

대표 가격에 적용할 때는 추정 분류임을 명시하며, 공식적인 원산지·상품 상태 정보가 확인되면 해당 정보를 우선 적용한다. 상세 적용 원칙은 `PD-013`을 따른다.


## 3. 왜 15일 단위로 가격을 보여줄까?

수산물 가격은 날씨, 어획량, 물류 상황 등에 따라 자주 변한다.

하루 가격만 보면 그래프가 너무 복잡하고, 한 달 평균만 보면 가격 변화를 늦게 확인할 수 있다.

그래서 오늘의 수산은 **15일 단위 평균가격**을 기본으로 선택했다.

| 표시 주기 | 장점 | 단점 |
|---|---|---|
| 일별 | 매일의 변화 확인 가능 | 가격 변동이 심해 흐름 파악이 어려움 |
| **15일별** | 변화를 확인하면서 전체 흐름도 파악 가능 | 하루 단위 변화는 생략 |
| 월별 | 장기적인 가격 흐름 파악에 좋음 | 단기 변화를 놓칠 수 있음 |

### 3.1. 평균가격 계산 방법

**15일마다 데이터를 수집하는 것이 아니다.**

매일 수집한 가격을 저장한 뒤 1~15일과 16일~말일로 나눠 평균을 계산한다.

예를 들어 다음과 같은 가격이 있다고 가정하자.

| 날짜 | 시장별 가격을 평균한 하루 가격 |
|---|---:|
| 7월 1일 | 10,000원 |
| 7월 2일 | 12,000원 |
| 7월 3일 | 가격 없음 |
| 7월 4일 | 11,000원 |

7월 1~15일에 위 3일만 가격이 관측됐다면 다음과 같이 계산한다.

```text
(10,000 + 12,000 + 11,000) ÷ 3
= 11,000원/kg
```

가격이 없는 7월 3일은 계산에서 제외한다.

실제 화면에는 다음처럼 표시한다.

```text
7월 상반기
평균가격: 11,000원/kg
가격 관측일: 3일
```

같은 날짜에 여러 시장의 가격이 있다면 **시장별 가격을 먼저 단순 평균**한다.

예를 들어 서울 10,000원, 광주 12,000원, 대전 11,000원이면 그날 평균은 11,000원이다.

이후 날짜별 평균들을 15일 또는 월 단위로 다시 평균한다.

## 4. 어떤 API를 사용했을까?

API는 **다른 컴퓨터에 필요한 정보를 요청하고 응답받는 통로**다.

예를 들어 음식점에서 메뉴를 주문하면 음식을 받는 것처럼, 프로그램은 API에 데이터를 요청하고 결과를 받는다.

오늘의 수산은 역할이 다른 두 API를 사용했다.

### 4.1. KAMIS 가격 API

**역할:** 시장에서 조사한 수산물 판매가격을 제공한다.

- 제공기관: 한국농수산식품유통공사(aT)
- 사용 데이터: 일별 중도매인 판매가격
- 주요 정보: 날짜, 품목, 품종, 등급, 시장, kg당 가격
- MVP 활용: 수산물 대표 가격 차트

**사용한 API**

```text
공공데이터포털 일별 도·소매 가격정보
https://apis.data.go.kr/B552845/perDay/price
```

초기 검증에는 KAMIS의 기간별 가격조회 API도 사용했다.

```text
https://www.kamis.or.kr/service/price/xml.do
action=periodProductList
```

**요청 예시: 갈치 가격 조회**

```http
GET https://apis.data.go.kr/B552845/perDay/price
?serviceKey=YOUR_KEY
&returnType=JSON
&pageNo=1
&numOfRows=1000
&cond[exmn_ymd::GTE]=20251001
&cond[exmn_ymd::LTE]=20251031
&cond[ctgry_cd::EQ]=600
&cond[se_cd::EQ]=02
&cond[item_cd::EQ]=613
```

주요 요청값의 뜻은 다음과 같다.

| 요청 항목 | 의미 |
|---|---|
| `serviceKey` | API 이용 인증키 |
| `exmn_ymd` | 가격 조사 날짜 |
| `ctgry_cd=600` | 수산물 분류 |
| `se_cd=02` | 중도매 가격 |
| `item_cd=613` | 갈치 |

**실제 관측 응답에서 필요한 값만 발췌한 예시**

```json
{
  "exmn_ymd": "20251001",
  "item_cd": "613",
  "item_nm": "갈치",
  "vrty_cd": "01",
  "vrty_nm": "생선",
  "grd_nm": "中",
  "mrkt_nm": "가락도매",
  "exmn_dd_cnvs_prc": "21800"
}
```

이 응답은 다음과 같이 읽을 수 있다.

> 2025년 10월 1일, 가락도매시장에서 조사한 갈치(생선·中)의 kg당 가격은 21,800원이다.

여기서 가져오는 값은 **중도매인 판매가격**이며, 소비자 소매가격이나 경매 낙찰가격과는 다르다.

### 4.2. 공공데이터포털 도매시장 정산정보 API

**역할:** 도매시장에서 실제로 거래된 수산물의 수량과 총금액을 제공한다.

- 제공기관: 한국농수산식품유통공사(aT)
- 사용 데이터: 전국 공영도매시장 정산정보
- 주요 정보: 거래 날짜, 시장, 품목 코드, 거래중량, 거래금액
- MVP 활용: Price Insight의 거래량 참고 지표

**사용한 API**

```text
https://apis.data.go.kr/B552845/katSale/trades
```

**요청 예시: 광주서부도매시장 전복 정산정보 조회**

```http
GET https://apis.data.go.kr/B552845/katSale/trades
?serviceKey=YOUR_KEY
&returnType=JSON
&pageNo=1
&numOfRows=1000
&cond[whsl_mrkt_cd::EQ]=240004
&cond[trd_clcln_ymd::EQ]=2026-07-01
&cond[gds_lclsf_cd::EQ]=72
&cond[gds_mclsf_cd::EQ]=09
```

| 요청 항목 | 의미 |
|---|---|
| `whsl_mrkt_cd=240004` | 광주서부도매시장 |
| `trd_clcln_ymd` | 거래 정산 날짜 |
| `gds_lclsf_cd=72` | 신선 해면패류 |
| `gds_mclsf_cd=09` | 전복 상품군 |

**실제 거래 응답에서 필요한 값만 발췌한 예시**

```json
{
  "trd_clcln_ymd": "2026-07-01",
  "whsl_mrkt_cd": "240004",
  "gds_lclsf_cd": "72",
  "gds_mclsf_cd": "09",
  "gds_sclsf_cd": "04",
  "gds_sclsf_nm": "참전복",
  "unit_nm": "kg",
  "unit_tot_qty": "10.000",
  "totprc": "179000.000"
}
```

이 응답은 다음과 같이 읽을 수 있다.

> 2026년 7월 1일 광주서부도매시장에서 참전복 10kg이 총 179,000원에 정산됐다.

kg당 정산가격은 다음과 같이 계산한다.

```text
179,000원 ÷ 10kg = 17,900원/kg
```

여러 거래의 평균가격을 계산할 때는 다음 방식을 사용한다.

```text
kg당 정산가격
= 전체 거래금액의 합 ÷ 전체 거래중량의 합
```

**주의:** 정산가격과 KAMIS 판매가격은 서로 다른 가격이다. 따라서 두 가격을 하나의 평균으로 섞지 않는다.

## 5. 왜 품목 코드 매핑 테이블이 필요할까?

### 5.1. 품목 코드란?

품목 코드는 상품에 붙이는 **고유한 분류 번호**다.

학교에서 같은 학생에게도 학번과 도서관 회원번호가 따로 있을 수 있는 것처럼, 같은 수산물도 데이터를 관리하는 기관마다 다른 코드를 사용한다.

예를 들어 갈치는 다음과 같다.

```text
KAMIS
갈치 = 613

공공데이터포털 정산정보
신선 어류 / 갈치 = 71 / 04
```

숫자는 다르지만 두 데이터는 모두 갈치와 관련된다.

이렇게 다른 번호를 연결해 주는 표가 **품목 코드 매핑 테이블**이다.

### 5.2. 기관마다 코드가 다른 이유

두 기관이 기록하려는 정보가 다르기 때문이다.

| 구분 | KAMIS | 공공데이터포털 정산정보 |
|---|---|---|
| 주요 목적 | 가격 조사 | 실제 거래 기록 |
| 중요 정보 | 품목·품종·등급·시장 | 거래품목·상태·세부 종류·수량 |
| 예시 | 갈치 / 생선 / 中 | 신선 어류 / 갈치 / 은갈치 |
| 활용 | 평균가격 차트 | 거래량·정산가격 분석 |

KAMIS는 **얼마에 판매하는지**를 알려주고, 정산정보는 **무엇이 얼마나 거래됐는지**를 알려준다.

그래서 두 코드를 무조건 같은 상품이라고 취급하면 안 된다.

### 5.3. MVP 어종별 품목 코드 매핑 테이블 v1

| 어종 | KAMIS 품목코드 | KAMIS 품종코드 | 공공데이터포털 대분류 | 중분류 | 확인된 세부 코드 예시 | 매핑 수준 |
|---|---|---|---|---|---|---|
| **갈치** | `613` | `01` 생선 | `71` 신선 해면어류 | `04` 갈치 | `01` 먹갈치, `02` 은갈치 | 상품군 매핑 |
| **고등어** | `611` | `01` 생선 | `71` 신선 해면어류 | `06` 고등어 | `01` 망치고등어, `03` 점고등어 | 상품군 매핑 |
| **전복** | `653` | `00` 냉장 | `62` 활 해면패류 / `72` 신선 해면패류 | `09` 전복 | `62/09/03` 활 참전복, `72/09/04` 신선 참전복 | 상품군 매핑 |

**코드 읽는 방법**

예를 들어 `71/04/02`는 다음과 같다.

```text
71 = 신선 해면어류
04 = 갈치
02 = 은갈치
```

전복은 살아 있는 상태와 신선 상태가 별도 대분류이기 때문에 두 가지 분류를 연결한다.

이 매핑 테이블은 **같은 상품군을 찾는 1차 연결표**다. 세부 품종·등급·원산지·크기까지 완전히 같은 상품이라는 의미는 아니다.

따라서 실제로 거래량과 가격을 비교할 때는 시장, 날짜, 상태 등도 추가로 확인해야 한다.

## 6. 결측값은 어떻게 표현할까?

### 6.1. 결측값이란?

**결측값**은 데이터가 없는 상태다.

예를 들어 6월에 고등어 가격을 조사한 기록이 없다면 그 기간의 가격은 알 수 없다.

가격을 알 수 없다고 해서 **0원이라는 뜻은 아니다.**

### 6.2. 차트 표시 정책

| 상황 | 차트 표시 | 사용자 안내 |
|---|---|---|
| 정상적인 가격 기록 존재 | 점과 실선 표시 | `평균 11,000원/kg` |
| 해당 15일 구간에 가격 기록 없음 | 선 끊기 + 연한 회색 영역 | `가격 조사자료 없음` |
| API 오류로 데이터 수집 실패 | 선 끊기 | `수집 오류로 확인 중` |
| 비교 가능한 품종·등급 없음 | 선 끊기 | `비교 가능한 가격 없음` |

다음과 같은 방식은 사용하지 않는다.

- 가격이 없다고 **0원으로 표시하지 않는다.**
- 결측 구간의 양옆 가격을 **임의로 연결하지 않는다.**
- 이전 가격을 복사해 채우지 않는다.
- 생물 가격이 없다고 냉동 가격으로 대체하지 않는다.

가격과 함께 **관측일 수와 시장 수**를 제공하면 데이터가 얼마나 충분한지도 알 수 있다.

## 7. PoC 검증 결과와 결론

### 7.1. 검증 결과

| 검증 항목 | 결과 |
|---|---|
| KAMIS 가격 API 호출 | 검증 완료 |
| 수산물 1년치 가격 수집 | 검증 완료 |
| 시장별 단순 평균가격 계산 | 검증 완료 |
| 15일·월별 가격 차트 | 검증 완료 |
| 가격 결측 구간 확인 | 검증 완료 |
| 정산정보 API 거래량·거래금액 조회 | 일부 날짜·시장 검증 |
| 품목 코드 매핑 테이블 | 상품군 수준 v1 정의 |
| 두 기관의 정확한 세부 상품 1:1 매핑 | 추가 검증 필요 |
| 거래량 변화가 가격 변동을 일으킨다는 분석 | 검증되지 않음 |

### 7.2. 최종 결론

**오늘의 수산 MVP에 필요한 수산물 가격 차트는 구현 가능하다.**

갈치와 전복은 1년 동안 모든 15일 구간에 가격이 존재했으며, 고등어도 대부분의 기간에서 가격이 확인됐다.

따라서 **갈치·고등어·전복**을 MVP 최초 제공 품목으로 사용한다.

가격 차트는 KAMIS 중도매 가격을 기준으로 15일·월별 평균을 제공한다.

공공데이터포털 정산정보는 거래량과 정산금액을 분석하는 참고자료로 사용한다.

다만 **거래량이 줄었다는 사실과 가격이 올랐다는 사실을 동시에 관측했더라도, 거래량 감소가 가격 상승의 원인이라고 단정해서는 안 된다.**

Price Insight에서는 우선 확인된 사실과 가능한 해석을 구분해 제공한다.

### 7.3. MVP 개발 전 검증 적용 범위

1. 갈치·고등어·전복의 국산 생물 추정 평균가격 검증
2. 일별 원본 데이터 저장 및 15일·월별 가격 집계
3. 가격 차트의 결측값 표시
4. 기관별 품목 코드 매핑 테이블 관리
5. 매핑 조건이 확인된 정산 거래량을 Price Insight 참고자료로 활용
6. PoC 내부에서 KAMIS 품목명·품종명에 '수입' 표시가 없으면 국산으로 추정
7. PoC 내부에서 '냉동' 표시가 없으면 생물로 추정하되, 건조·건어류는 제외
8. 원본 품종명과 자동 분류 결과를 각각 저장하여 추후 검증 및 수정 가능하도록 관리


> **최종 판단: 가격 차트 기술 검증 완료 및 초기 제공 품목 확정**
>
> 가격 차트의 기술적 구현 가능성을 확인했으며, 코드 매핑의 한계와 결측값 처리 원칙을 정의했다. 갈치·고등어·전복은 후속 제품 검토를 거쳐 초기 제공 품목으로 확정했으며, 추정 분류의 사용자 노출 정책은 상위 제품 결정을 따른다.
