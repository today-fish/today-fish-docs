# FG-001 Figma 설계 및 단계별 승인 기준

> **핵심 결론:** 오늘의 수산 Figma 산출물은 GitHub의 PRD·PF·UX 요구사항을 준수한다. 각 Phase는 사용자 승인 뒤 다음 단계로 넘어가며, 같은 Phase 안의 승인 범위는 일괄 수행할 수 있다. 디자인 검토와 최종 서비스 검증은 분리한다.

- 문서 상태: **통합 반영용 초안**
- 적용 플랫폼: 모바일 웹
- 원본 정책: Phase 1 v1.0 Q1~Q20, v1.1 Q21~Q46 및 Q18 후속 개정
- 제품 원본: `PRD-001`, `PF-001~005`, `UX-001`, `UX-002`, `DS-001`

## 1. 역할과 범위

이 문서는 Figma 제작의 승인 체계와 최상위 디자인 원칙을 명시한다. 제품 범위, 가격 산식, 채팅 서버 규칙은 기존 PRD·PF 문서에서 관리한다. 화면 세부 정책은 UX-001·002, 컴포넌트는 FG-002, 프로토타입은 FG-003이 담당한다.

## 2. 공통 설계 원칙

1. 갈치·고등어·전복 3종의 모바일 웹 MVP를 설계한다.
2. `SCR-*`, `ST-*`, `UF-*`, `UX-D*`, `FR-*`의 원본 식별자를 보존한다.
3. 브랜드 컨셉은 Ocean Minimal + Fresh & Friendly를 따른다.
4. 기본 디자인 너비는 **390px**, 브라우저 에뮬레이터 검증 너비는 **320px·390px·480px**이다. 이 수치는 새 breakpoint 정의가 아니다.
5. 차트 선택 정보는 CSS viewport 767px 이하에서 하단 고정 정보 영역, 768px 이상에서 차트 내부 툴팁으로 표시한다. 768px은 표준 필수값이 아닌 제품 설계 기준이며, 767px·768px 경계를 검증한다. 선정 근거의 상세 설명은 [UX-002](../../MVP/product/ux/UX-002-화면-상태-및-인터랙션-설계.md)와 [FG-003](./FG-003-화면-상태-프로토타입-설계.md)을 참조한다.
6. Pretendard를 우선 사용한다. Figma에서 미지원 시 Noto Sans KR을 우선 대안으로 검토하고, 웹은 Apple SD Gothic Neo·Malgun Gothic 등 시스템 폰트 Fallback을 우선 사용한다.
7. 디자인 토큰 단일 원본은 GitHub `design-system/tokens/tokens.json`이며 Figma Variables·Styles는 동기화 대상이다.
8. 기술 도구의 한계를 이유로 승인된 UX 범위를 임의 축소하지 않는다.

## 3. 작업 단계 및 승인 게이트

| 단계 | 산출물 | 다음 단계 진행 조건 |
|---|---|---|
| Phase 1 | 통합된 요구사항·설계 정책 문서 | 사용자 문서 검토·승인 |
| Phase 2 | Foundations, Variables, Styles | 사용자 토큰/디자인 검토·승인 |
| Phase 3 | Primitives, Patterns, Variants | 사용자 컴포넌트 검토·승인 |
| Phase 4 | UI Screens, 정상·예외 상태 | 사용자 화면 검토·승인 |
| Phase 5 | UF-01~06 흐름도 및 클릭형 Prototype | 사용자 흐름·상호작용 검토·승인 |

같은 단계의 **이미 승인된 작업 범위**는 묶어서 수행할 수 있다. 새 요구사항, 범위 변경, 원본 정책 충돌, 토큰 원본 수정, Figma 페이지 구조 변경은 명시적 별도 승인을 요구한다.

## 4. 디자인 완료와 서비스 완료

- **Design 단계:** 요구사항 연결성, 토큰 일치, 컴포넌트 일관성, 정상·로딩·결측·오류·복구 상태, 반응형 레이아웃을 검토한다.
- **Prototype 단계:** Figma Present에서 UF-01~06과 주요 예외를 실제 실행해 기록한다. 수동 연결 명세만 작성한 상태는 실행 검증 PASS가 아니다.
- **Implementation 단계:** 실제 UI·서버/API·채팅 동작을 구현하고 테스트한다.
- **최종 검증 단계:** WCAG 2.2 AA 자동·수동 점검, 320·390·480px 브라우저 에뮬레이터, UF 정상·예외 E2E와 PRD의 비기능 요구사항을 확인한다. **실기기 테스트는 필수 PASS 조건에서 제외**한다(Q18 후속 개정 및 Q44).

단계별 검증 결과는 `FV-001`에서 개별 열로 관리한다. 출시 인수 판정은 `PP-003`의 독립 기준을 따른다.
