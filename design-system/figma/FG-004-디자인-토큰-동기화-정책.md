# FG-004 디자인 토큰 동기화 정책

> **핵심 결론:** `design-system/tokens/tokens.json`이 유일한 디자인 토큰 원본이다. Figma Variables·Styles는 승인형 동기화 대상이며, 원본과 Figma의 차이는 감지·보고한 후 사용자 승인으로 해결한다.

- 문서 상태: 통합 반영용 초안
- 관련 승인: Q10, Q17, Q40~Q42, Q46

## 1. 원본과 권한

- **SSOT:** GitHub `design-system/tokens/tokens.json`
- **파생 대상:** Figma Variables·Styles
- Figma의 시각적 수정을 원본 정책으로 자동 역반영하지 않는다.
- 기존 디자인 시스템의 토큰 상태(carried, Draft, Proposal 등)는 각각 보존하고, 파일에 존재하는 값이 곧 최종 승인임을 뜻하지 않도록 한다.

## 2. 동기화 절차

1. GitHub 원본과 Figma의 토큰 이름·타입·값·참조 관계를 비교한다.
2. 추가·수정·삭제 항목과 토큰 승인 상태, 충돌 목록을 정리한다.
3. 변경 영향 화면·컴포넌트를 식별한다.
4. 사용자에게 동기화 대상과 충돌 해결안을 제시하여 승인받는다.
5. 승인된 변경만 Figma에 동기화한다.
6. 동기화 후 값·타입·명칭·참조 일치 및 영향 화면을 검증한다.

## 3. 충돌 처리

- GitHub와 Figma의 값이 다르면 차이를 보고하고 변경 근거를 확인한다.
- GitHub 원본을 수정해야 할 정당한 사유가 있으면 **원본 변경 승인 후** 수정·동기화한다.
- Figma만 잘못 수정된 경우 승인 후 Figma 값을 원본 상태로 복원한다.
- 자동 덮어쓰기나 Figma → GitHub 자동 역동기화는 하지 않는다.

## 4. 화면 영향 검증

- 단일 컴포넌트/토큰 범위의 변경은 참조 관계에 따라 영향 화면·Variant·상태를 검증한다.
- 전역 토큰 변경은 전체 화면을 검증한다(Q17·Q42).
- 결과와 증빙은 `FV-001` 요구사항 추적 체계에 연결한다.

## 5. Draft 시안 값의 취급

Q46에 따라 FAB 크기 `56px`, 화면 여백 `20px`, 채팅 패널 높이 `55dvh`, 모션 `180ms`·`200ms` 등 **기존 Draft 치수·모션은 시안 제작의 초기 기준**으로 사용할 수 있다. 실제 화면과 접근성 검토를 거친 후 별도로 최종 승인한다. 동기화 동작이 이 승인 상태를 임의로 변경해서는 안 된다.
