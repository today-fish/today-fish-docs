# FV-002 Override 및 컴포넌트 의존성 관리

> **핵심 결론:** 인스턴스 콘텐츠·Component Property는 수정할 수 있다. 예외적인 스타일 Override는 GitHub docs에 사유를 기록하며, Figma에는 참조 ID와 링크를 연결한다. 변경 영향을 받는 화면·상태를 추적해 검증한다.

- 문서 상태: 통합 반영용 초안
- 관련 승인: Q12, Q16~Q17, Q21~Q23, Q38~Q39

## 1. Override 허용 범위

| 변경 종류 | 처리 |
|---|---|
| 콘텐츠·정의된 속성 | 인스턴스에서 허용 |
| 스타일 예외 | 사유를 GitHub에 기록 후 허용 |
| 구조적 차이 | Variant 또는 Pattern 승격 여부 검토 |
| 전역 토큰 변경 | 토큰 SSOT 절차 및 전체 화면 검증 |

## 2. Override 기록 내용

- 추적 ID(별도 고유 식별자), 원본 컴포넌트명, 대상 Figma 화면·인스턴스
- 변경 속성 및 기존값·변경값
- 예외가 필요한 사유, 관련 PRD/PF/UX 요구사항
- 담당 검토자와 승인 근거(해당하는 경우)
- 관련 GitHub PR·Figma 링크, 영향받는 화면

기록의 원본은 GitHub docs이며 Figma에는 추적 ID·링크만 남긴다. 사용 횟수와 재사용 예정 근거가 충족되면 컴포넌트 승격을 재검토한다.

## 3. 의존성 관계

`Primitive → Pattern → Screen/State` 참조 관계를 추적한다.

1. Figma의 읽기 전용 추출 기능이 사용 가능하면 관계 수집에 우선 활용한다.
2. 자동 추출이 불가능하거나 누락된 관계는 GitHub 의존성 목록으로 보완한다.
3. 수집한 관계의 실제 사용 위치를 확인하고 빠진 경로를 정정한다.
4. 컴포넌트 변경 때 영향 화면·Variant·상태를 식별해 검증하고 증빙을 `FV-001`에 연결한다.
5. 글로벌 토큰 변경은 영향 대상 선별 대신 전체 검증한다.
