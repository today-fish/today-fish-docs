# FV-001 요구사항 추적 및 검증 상태

> **핵심 결론:** 요구사항과 설계·검증 증빙의 단일 관리 기준은 GitHub docs의 추적표이다. Design, Prototype, 구현, 최종 검증을 독립된 열로 관리하고 공통 상태값 6종을 사용한다.

- 문서 상태: 통합 반영용 초안
- 관련 승인: Q18~Q20, Q29, Q35~Q37, Q45

## 1. 추적 대상과 관계

- 원본 요구사항: PRD의 `CAP-*`, PF의 `FR-*`, UX의 `UX-D*`, `UF-*`, `SCR-*`, `ST-*`.
- Figma에는 원본 ID와 GitHub 링크를 부착한다.
- GitHub 추적표에는 문서 원본, 연결 컴포넌트/화면, PR, 검증 기록을 해당 단계에 연결한다.
- 변경 이력은 기존 GitHub PR과 커밋을 활용한다. 독립적인 중복 변경 로그를 필수로 만들지 않는다.

## 2. 검증 열

| 열 | 범위 |
|---|---|
| Design | 해당 UI 설계 및 요구사항 정합성 |
| Prototype | Present 실행 검증 |
| Implementation | 실제 코드·연동 구현 검증 |
| Final Verification | 접근성·반응형·E2E·비기능 요구사항의 최종 검증 |

검증 열은 독립적이다. 해당 단계가 요구사항에 해당되지 않으면 `N/A`로 기록한다. 서비스 최종 완료와 `PP-003` 출시 판정은 별도이다.

## 3. 공통 상태값

| 상태 | 의미 | 판정 메모 |
|---|---|---|
| `NOT_STARTED` | 아직 시작하지 않음 | 기본값 |
| `IN_PROGRESS` | 작업/검증 중 | 진행 근거 연결 가능 |
| `PASS` | 해당 단계 합격 기준 충족 | 결과 증빙 필수 |
| `FAIL` | 시험·검증했으나 기준 불충족 | 실패 조건 명시 |
| `BLOCKED` | 의존성·환경 제약으로 검증 불가 | 차단 사유·해소 조건 명시 |
| `N/A` | 해당 단계가 적용되지 않음 | 적용 제외 사유 권장 |

## 4. 최소 추적표 스키마

| 필드 | 설명 |
|---|---|
| `requirement_id` | 변경하지 않는 원본 ID |
| `source_link` | 원본 PRD/PF/UX 링크 |
| `figma_ref` | Figma 화면·상태 프레임 링크 (해당 시) |
| `design_status` | 공통 상태값 |
| `prototype_status` | 공통 상태값 |
| `implementation_status` | 공통 상태값 |
| `final_status` | 공통 상태값 |
| `evidence_links` | 단계별 테스트·PR·캡처 등 |
| `notes` | 차단·실패·적용 제외 근거 |

## 5. 운영 규칙

- 실제 수행하지 않은 검증은 `PASS`로 기록하지 않는다.
- 변경이 발생하면 영향 관계를 `FV-002`와 연결하여 관련 검증을 다시 수행한다.
- Figma의 시안 승인만으로 기능 구현 또는 출시 완료를 판정하지 않는다.
- 최종 검증 요구사항에는 Q43~Q45 기준을 적용한다.
