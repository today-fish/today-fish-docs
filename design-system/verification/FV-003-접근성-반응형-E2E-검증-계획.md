# FV-003 접근성·반응형·E2E 검증 계획

> **핵심 결론:** 최종 서비스 검증은 WCAG 2.2 AA 자동·수동 검사, 320·390·480px 브라우저 에뮬레이터, UF-01~06 정상·주요 예외 및 기존 PRD 비기능 요구사항 검증 결과를 포함한다. 실기기 검증은 필수 PASS 조건에서 제외한다.

- 문서 상태: 통합 반영용 초안
- 관련 승인: Q17~Q18(후속 개정 포함), Q29, Q43~Q45

## 1. 검증 책임 분리

| 구분 | 인수 대상 |
|---|---|
| Design | 시각 일관성·구성·토큰·원본 요구사항 정합성 |
| Prototype | Figma Present에서 실행한 UF 및 예외 흐름 |
| Implementation | 실제 UI·API·채팅 기능 동작 |
| Final Verification | 접근성·반응형·E2E·성능·부하·보안 등 필수 기준 |

## 2. 접근성 검증

- 목표: **WCAG 2.2 AA**.
- 자동 검사 도구와 키보드·스크린리더·시각적 수동 검증을 병행한다.
- 명도 대비, 포커스 표시, 키보드 순서, 인터랙션 설명, 입력 오류 피드백, 콘텐츠 구조와 터치 대상 등을 점검한다.
- 닉네임 20색은 모든 실제 사용 배경에서 일반 텍스트 **최소 4.5:1**을 만족해야 하며, 색 외에 닉네임 텍스트로도 사용자를 구별한다. 테마별 색상 매핑은 허용한다.
- 자동 도구 통과만으로 접근성 완료를 선언하지 않는다.

## 3. 반응형·브라우저 검증

- 브라우저 에뮬레이터에서 모바일 너비 **320px·390px·480px**을 검사하고, 각 너비에서 차트 하단 고정 정보 영역이 표시되는지 확인한다.
- 차트 데이터/정보 영역, 검색 결과, 탭, 채팅 오버레이, 소프트 키보드 시뮬레이션, 스크롤 및 오류 메시지의 접근성을 확인한다.
- CSS viewport **767px**에서 차트 하단 고정 정보 영역, **768px**에서 차트 내부 툴팁이 표시되는지 전환 경계를 확인한다. 768px 이상은 넓은 화면 기준으로 검증한다.
- 전환 전후에 선택 기간과 평균가격이 유지되는지 확인한다.
- 툴팁이 화면 가장자리에서 잘리거나 차트 데이터·축을 가리지 않는지 확인한다.
- 결측 구간을 터치해도 기존 유효 선택 및 Price Insight가 유지되는지 확인한다.
- **실제 스마트폰 테스트는 최종 PASS 필수 조건이 아니다.** 별도 수행한다면 결과를 추가 증빙으로 관리한다.

## 4. E2E 및 비기능 검증

- UF-01~06의 정상 흐름과 가격 결측·API 오류·이슈 없음·채팅 단절/복구 등 주요 예외를 검증한다.
- 차트 집계 및 선택 기간·Insight 동기화는 실제 데이터·API와 함께 검증한다.
- 채팅은 권한·익명 식별·세션 복원·메시지 실패와 기존 PRD·PF의 동시 접속/빈도/보존 정책을 검증한다.
- 기존 PRD·PF·PP-003에 명시된 성능·부하·보안 및 출시 차단 기준을 유지한다. 새 목표치를 임의로 정하지 않는다.
- 구현·서비스 기능의 합격 여부는 Figma UX 시뮬레이션만으로 대체하지 않는다.

## 5. 증빙과 판정

- 요구사항 ID, 대상 환경, 수행자·시점, 행동 및 기대 결과, 실제 결과, 상태, 증빙 링크를 기록한다.
- 상태는 `FV-001`의 6종을 사용한다.
- 기능별·단계별 `PASS`와 제품 출시 인수(`PP-003`)를 별개로 관리한다.
