# 오늘의 수산 — GitHub 운영 가이드

오늘의 수산의 Issue, 통합 GitHub Project, PR을 이용해 개발 작업을 관리할 때 읽는 안내서다. 처음 합류했다면 아래 **처음 시작하기**를 따라가고, 진행 중인 작업이 있다면 **지금 어떤 작업을 하시나요?**에서 필요한 문서로 바로 이동하면 된다.

GH-001~006은 현재 **V1 / 승인**이다. 실제 GitHub 설정으로 확인한 내용과 아직 검증하지 못한 동작은 각 문서에서 구분한다.

## 처음 시작하기

1. 아래 **운영 구조**에서 세 저장소와 통합 Project를 확인한다.
2. [Issue 필드 선택 기준](GH-001-이슈-분류-및-필드-정책.md)으로 Type·Level·Workstream의 차이를 이해한다.
3. 기능을 여러 작업으로 나눈다면 [L1/L2 분할 기준](GH-003-작업-계층-및-분할-기준.md)을 읽는다.
4. Issue를 작성할 때 [복사용 본문 예시](GH-004-이슈-템플릿-및-작성-기준.md)와 [실제 라벨 목록](GH-002-저장소별-라벨-정책.md)을 사용한다.
5. 진행 상황은 [Project View·Status 가이드](GH-005-프로젝트-뷰-및-자동화-정책.md)에서, PR부터 완료·유지보수까지는 [작업 흐름 가이드](GH-006-이슈-PR-생명주기-및-변경-관리.md)에서 확인한다.

모든 문서를 순서대로 정독할 필요는 없다. 현재 해야 할 일에 맞는 문서부터 읽어도 된다.

## 운영 구조

| 위치 | 관리하는 일 |
|---|---|
| `today-fish/today-fish-docs` | 제품·기술 설계 문서와 기능·독립 기술 목표의 L1 Issue |
| `today-fish/today-fish-backend` | 백엔드 구현·검증 Issue |
| `today-fish/todat-fish-frontend` | 프론트엔드 구현·검증 Issue |

세 저장소의 작업은 단일 [GitHub Project #1 — 오늘의 수산-MVP Development](https://github.com/orgs/today-fish/projects/1)에서 함께 본다. `todat-fish-frontend`는 현재 저장소의 실제 이름이다. Issue를 둘 저장소와 Project의 Workstream은 서로 다른 기준이므로 [필드 선택 가이드](GH-001-이슈-분류-및-필드-정책.md)에서 함께 확인한다.

## 신규 기능의 기본 흐름

예를 들어 가격 차트를 개발한다면 Docs에 기능 전체의 L1을 만들고, Backend·Frontend에 검증 가능한 L2를 나눈다. 각 Issue에 기준 문서·완료 조건을 적고 상위 L1과 연결한다. Repository 간 Parent/Sub-issue 연결 동작은 아직 검증되지 않았으므로 L1 링크를 본문에도 남긴다. 이후 필드·라벨을 설정하고 Project에 등록한 뒤, L2별 PR과 검증 결과를 연결한다. PR 병합 후에는 L2의 Issue·Project 상태와 L1 자체의 인수 조건을 차례로 확인한다.

분할 판단은 [GH-003](GH-003-작업-계층-및-분할-기준.md), Issue 본문은 [GH-004](GH-004-이슈-템플릿-및-작성-기준.md), Project와 완료 처리는 [GH-005](GH-005-프로젝트-뷰-및-자동화-정책.md)·[GH-006](GH-006-이슈-PR-생명주기-및-변경-관리.md)을 따른다.
